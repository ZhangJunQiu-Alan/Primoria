这是对当前实现成熟度的判断，不是功能数量评分。分数用于比较改进优先级，不代表行业认证。

一句话架构评价

方向正确：Next.js 负责产品与数据写入，LangGraph 负责 AI 编排，PostgreSQL 负责任务、课程与学习状态，Worker 负责长任务。这个分工符合当前产品阶段。

最有价值的现有资产

  • 课程生成已拆成 Planner、确定性 Compiler、Writer、Validator 和版本化 checkpoint。
  • Lesson、Progress、Extractor 三类任务都有 lease、fencing、SKIP LOCKED、重试和 DB 竞态测试。
  • KG infrastructure failure 与 coverage miss 已分开，不会把系统故障伪装成自由课程。
  • 交互可视化有多种结构化 renderer，Widget allowlist 已有 Web/Agent 同步测试。
  • 课程阅读器聚焦单步学习，AI Tutor 保持课程上下文，真实浏览器 QA 主路径可用。

当前最大风险

  • 模型生成脚本运行在可同源、可弹窗逃逸的 iframe sandbox 中。
  • 用户 Provider API key 明文存 DB，并通过 GET 返回浏览器写入 localStorage。
  • Quiz 的 score/total 信任客户端；学习事件失败会被吞掉，但掌握度只读事件流。
  • 生产无部署编排、Tracing、告警、错误聚合和任务运维界面。
  • CI 不运行 Agent 单测、DB 集成测试、KG 验证和真实浏览器主路径。

模型生成 Widget 的 iframe 隔离可被同源脚本削弱

widget-renderer.tsx:824,837 同时启用 allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox。Widget 是模型生成的不可信 JS，这种组合不应作为安全边界。

更安全的方向

移除 same-origin、popups 与 escape；优先 opaque-origin sandbox="allow-scripts"。如确需同源能力，改为独立 Widget origin，并用严格消息协议和 URL 白名单桥接。

R2
P0

BYOK API key 明文存储并回传浏览器，且 baseUrl 缺少 SSRF 限制

user-settings.ts:37-40,72-91 把完整 settings 存入 JSONB；settings/provider/route.ts:14-27 返回完整值；course-ai-assistant-panel.tsx:589-613 再写入 localStorage。baseUrl 只校验为 string。

更安全的方向

服务端仅保存 secret handle；KMS/Vault 做 envelope encryption；GET 只返回 provider/model/configured/last4。限制 HTTPS、域名 allowlist，并拒绝 localhost、私网与 link-local 地址。

R3
P0

Quiz 信任客户端分数，学习证据与完成状态不是一个原子提交

quiz/route.ts:20-25,72-80 直接持久化客户端 score/total；即使 block 不存在仍可能写 course 级 attempt。事件写入会在 learning-events/store.ts:177-184 吞错，但 Progress Worker 只从事件流读取证据。

更安全的方向

服务端从课程 block 重算 score/total，拒绝无效 block/question。attempt、question evidence、lesson completion 与 outbox 在同一事务提交；Worker 从 outbox/权威 attempt 读取并提供 reconciliation。

R4
P0

未信任代理头时，所有登录请求共享同一个 unknown IP 限流桶

auth/rate-limit.ts:52-75 在默认配置下返回 unknown，仍构造全局 IP key。任意 6 次尝试可能影响其他账户，形成全站登录可用性风险。

更安全的方向

无法得到可信 IP 时跳过 IP bucket，仅保留 account/device bucket；部署时明确一层可信反向代理并覆盖 forwarding headers，配套配置启动检查。

P0

仓库没有 Web、Agent、3 Workers 的生产 Docker/Process manifest。可观测性主要是 console；/api/health 只覆盖 DB/KG。没有队列积压、lease 过期、provider 延迟/成本和失败率告警。

04 / STACK

技术栈：保留、补充与暂缓

建议以问题驱动增加技术栈。现有 Postgres 与 Worker 模型应继续使用，不应被“更潮”的组件替换。

领域决策建议为什么适合 Primoria
Web / BFF保留Next.js 16 + React 19SSR、App Router、route handlers 和现有产品边界匹配；没有拆前后端的必要。
AI orchestration保留LangGraph + CopilotKit工具编排、UI artifact 和课程上下文已经形成真实资产。重点是缩小 Graph 职责，不是换框架。
Primary data保留PostgreSQL + pgvector + Drizzle结构化学习状态、JSONB blocks、vector KG、job queue 都能在一个事务系统中处理。
Workflow queue保留现有 Postgres lease/fencing queue已通过并发与恢复测试。先补运维、outbox 和统一 runner，不引入 Redis。
Runtime contracts立即补共享 Zod schemas in packages/contracts消除 Agent/Web/tool renderer 多处手写 schema 与 z.any()，让漂移在编译/测试期失败。
Observability立即补OpenTelemetry + 一个后端贯穿 Next route、Agent、provider、Worker、DB job；能够回答首 token、课程完成、失败阶段和成本。
Secrets立即补SecretsProvider + KMS/Vault envelope encryptionProvider key 不再返回浏览器；以后可切换云 KMS，而业务代码只处理 secret handle。

Browser tests立即补Playwright CI smoke + accessibility assertions覆盖真实登录、建课、课程推进、恢复状态和 Widget sandbox；替代只靠静态字符串测试。

EdTech standards机构化后Caliper event vocabulary、QTI 3、LTI 1.3Caliper 对学习事件，QTI 对题目交换，LTI 对 LMS 接入；个人学习闭环稳定前不应抢优先级。

现在不建议增加

微服务当前团队与流量规模没有抵消网络和部署成本。
KafkaPostgres outbox 已足够解决当前证据一致性。
Redis / BullMQ会复制已通过验证的 Job 能力并增加运维组件。
独立向量数据库KG 与 learner data 仍适合 pgvector 的事务一致性。
Redux当前 UI 更需要拆组件状态机，不是增加全局状态容器。

06 / ROADMAP

下一步行动路线

顺序按“降低不可逆风险 → 建立可信证据 → 放大教育价值 → 扩组织能力”排列。

Week 1

关闭 Widget 与 BYOK 安全缺口

opaque-origin sandbox、消息协议、协议白名单、SecretsProvider、密钥轮换、SSRF 防护。

退出条件：恶意 Widget 无法读 parent/localStorage/API；GET 不返回 secret。
Week 1-2

让 Quiz 与学习事件成为可信事务

服务端评分、block/question 校验、attempt + evidence + completion + outbox 原子提交，增加 reconciliation。

退出条件：篡改 score/total 无效；任何 job 都能找到完整证据或明确失败。
Week 2

修正 Auth limiter 的 unknown bucket

无可信 IP 时不创建全局 IP key；加入部署配置检查与多用户回归测试。

退出条件：不同账户不会因 unknown IP 互相限流。
Week 2-3

建立生产拓扑与可观测性

Web/Agent/Workers 部署 manifest、连接池预算、OTel、job/provider metrics、告警与 runbook。

退出条件：能从一个 trace 定位请求、Agent、provider、job 与 DB 阶段。
Week 3-4

扩充 CI 的真实质量门

Agent typecheck/unit、Postgres migrations + DB tests、KG validate、Playwright smoke、sandbox security test。

退出条件：PR 绿灯覆盖最重要的运行时边界。
Month 2

Learning Evidence v2 与 Mastery confidence

事件版本、证据数、时间、难度、提示、confidence/retention；明确 mastered 最低证据合同。

产出：可解释、可回放、不会被 1/1 轻易抬升的 mastery。
Month 2

共享 runtime contracts，收缩巨型文件

Zod schemas 进入 contracts；拆 graph 工具/prompt/middleware；抽 shared worker runner；新 UI 用 CSS Modules。

产出：跨 runtime drift 由测试失败阻止，新增 renderer 不再改四处。
Month 2-3

诊断式 onboarding 与误区标签

基于目标 KG 生成短 placement；Quiz distractor 映射 misconception；推荐理由引用证据。

产出：起点更准，补救不再只依赖一个 weak 状态。
Month 3

间隔复习最小闭环

先定义 review item/state/log；再引入 FSRS 风格 retention 调度和每日 Review 页面。

产出：跨天回访理由明确，能测 7 日/30 日保持率。
