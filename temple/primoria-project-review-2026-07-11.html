P0

生产镜像启动 LangGraph 开发服务器，并把会话状态放在内存

docker/app.Dockerfile:34-37 在 NODE_ENV=production 下执行 langgraphjs dev；apps/agent/src/graph.mjs:34 使用 MemorySaver。进程重启会丢 checkpoint，开发 server 也不是受支持的生产拓扑。

更安全的方向

在保留单机 Compose 的前提下，使用受支持的 standalone Agent Server/生产构建，配置持久 checkpointer、readiness/liveness、优雅停机和固定镜像版本。

R2
P0

生产依赖审计有 12 个 high，直接依赖 Next.js 落后于安全修复

apps/web/package.json 固定 Next.js 16.1.6。2026-07-12 的 pnpm audit --prod 报告 8 low、28 moderate、12 high；Next 项包含 App Router Proxy bypass、Server Components DoS、连接耗尽和 SSRF 公告。其余 high 来自 form-data、hono、langsmith、ws，需做可达性确认。

更安全的方向

先升级并回归 Next 到覆盖全部公告的版本（审计当前指向至少 16.2.6），再升级/override 可达的传递依赖；CI 增加 production dependency audit，并记录临时豁免的 owner、理由和到期日。

R3
P0

Quiz 提交不是幂等操作，网络重试会重复增加掌握度证据

quiz/route.ts:22-25,98 请求没有 submission id，服务端每次生成新 attempt id。客户端在服务端已提交但响应丢失后重试，会写第二条 attempt 和第二组 quiz.submit 事件，最终把同一次答题计算两次。

更安全的方向

客户端创建稳定 submission id；数据库对 (owner_id, block_id, submission_id) 建唯一约束。重复请求返回第一次保存的 score/total，不再次写 evidence 或触发 completion。

R4
P1

容器、数据库角色和 secrets 没有最小权限隔离

docker/app.Dockerfile 没有非 root runtime stage，Web/Agent/Workers 保留完整源码、dev dependencies 和编译工具链。Compose 把同一个根 .env 注入所有进程；migration 与 runtime 共用由 Postgres image 创建的 primoria_app 超级用户。

更安全的方向

多阶段最小镜像 + 非 root 用户；migration role 与 runtime role 分离；按服务注入最少环境变量；只读文件系统和 capability drop 在验证后启用。

R5
P1

健康检查可能出现“HTTP 200 但关键队列未知”的假绿

health/route.ts:32-39 只有 queue 为 stalled 才降级，unknown 与 failed backlog 不影响总状态；degraded 仍返回 200。Compose 只有 PostgreSQL healthcheck，Web、Agent、Workers 与 Caddy 只依赖进程 started。

更安全的方向

拆 liveness/readiness；queue unknown 必须影响 readiness，failed/oldest-running/heartbeat 建独立指标和告警；Compose 依赖 service_healthy。再补 trace id、structured logs、provider latency/cost 和 job lifecycle metrics。

R6
P1

Extractor enqueue 在事务提交后 best-effort，失败会永久漏掉 learner facts

quiz/route.ts:176-186 在主事务后 enqueue，并只记录 console error。若数据库或进程在这个窗口失败，quiz/evidence 已提交，但没有可恢复记录要求后续提取。

更安全的方向

把 extractor intent 写进同一事务的 outbox，dispatcher 至少一次投递，job 唯一键负责去重；增加扫描“lesson completed 但无 extractor job”的 reconciliation。

R7
P1

备份只保存在同一台服务器，恢复能力没有被自动证明

scripts/pg-backup.sh:14-28 生成本机 gzip SQL 并保留 14 天。磁盘、主机或账号同时失效时备份一起丢失；仓库没有加密异地复制、恢复演练、恢复时间/恢复点目标或 PITR。

更安全的方向

加密上传对象存储并启用版本/保留策略；定期在隔离数据库自动恢复并校验关键表；定义 RPO/RTO。涉及 destructive migration 时准备 expand/contract 与回滚 runbook。

R8
P1

Web 边缘安全基线不一致：原始错误、同步密码 KDF、缺少标准 headers

多条 Course/KG route 直接返回任意 error.message；auth/password.ts:1-19 在请求线程执行 210k 次同步 PBKDF2；Next/Caddy 未配置 app-level CSP、HSTS、nosniff、Referrer/Permissions Policy。

更安全的方向

统一安全错误 mapper，只记录内部 cause + request id；改用异步 KDF（可评估 Argon2id）并做并发压测；在 Caddy/Next 建立可回归的 header baseline，先 report-only 验证 CSP。

R9
P1

关键状态机与数值范围仍主要依赖 TypeScript，而不是数据库约束

db/schema.ts:191-204,304-320,358-373,489-498 的 job status/stage/errorCategory/decisionStatus、quiz score/total、attempt/progress 数值没有完整 CHECK；人工 SQL 或未来代码路径可写入非法状态。

更安全的方向

用 forward migration 添加 CHECK：状态集合、0 ≤ score ≤ total、attempts/progress 非负、completed 状态的时间/lease 组合。先查询并清理违规行，再设为 validated。

R10
P1

掌握度模型仍把低样本比例当作稳定掌握

mastery/rules.ts:11-18 先要求 3 题全对，但下一条 ratio gate 又允许 2/2 直接 mastered。存储只保留最新 score/status，没有累计证据数、时间、提示、难度、置信度或遗忘信息。

更长期方向

先明确最小证据合同，再建设 append-only Evidence v2 和可回放聚合；mastery 输出 score + confidence + evidence count + last observed，间隔复习后再加入 retention。

R11
P2

界面仍有未兑现的产品合同

course-library-grid.tsx:925 生成不存在的 /learn/:courseId 分享链接；Upgrade CTA 只回到 Profile，没有 billing/subscription 状态。用户会把展示入口理解为已交付能力。

更安全的方向

未实现前隐藏入口；要上线分享则定义 snapshot、token、权限、撤销、preview/import；要上线付费则先建立 entitlement 与 webhook 幂等合同。

R12
P2

UI 与内容治理规模继续超过单文件和人工约定的承载能力

globals.css 14,514 行；Copilot hook 1,052 行、Library 1,048 行、Widget renderer 902 行；24 个 KG JSON 中只有 1 个 source map。历史 migrations 还会先创建再删除已退役 Workspace 表，虽无残留但增加 fresh bootstrap 噪声。

更长期方向

仅在修改热点时按 feature 切组件、样式和 state machine；新增 KG 强制 source/reviewer/version；历史 migration 保持不可变，只有当启动耗时或维护成本真实上升时再做受控 baseline squash。

06 / ROADMAP

下一步行动路线

先关闭发布阻断，再补可恢复副作用和运维闭环，最后扩展学习科学能力。

升级依赖并替换生产 Agent runtime

Next ≥16.2.6；处理可达 high advisories；production Agent Server + persistent checkpointer。

Week 1-2

让 Quiz submit 可安全重放

submission id、唯一约束、stored response；补并发/超时重试 DB tests。

退出条件：同一提交重复 2 次仍只有 1 attempt 与 1 组 evidence。
Week 2

为提交后副作用增加 outbox

先覆盖 extractor enqueue，再复用到其他“事务后 best-effort”路径。

退出条件：故障注入后 intent 可恢复、重复投递无重复业务结果。
Week 2-3

非 root 最小镜像、migration/runtime DB role、服务级 env、Agent/Web healthcheck。

退出条件：runtime 不能 DDL；queue unknown 使 readiness 失败；服务按 healthy 启动。
Week 3-4

建立观测、备份恢复与 Web edge baseline

trace/log/metrics、异地备份与 restore drill、统一错误、异步 KDF、安全 headers。

退出条件：能定位一次失败全链路；自动恢复校验通过；错误响应无内部信息。
Month 2

Learning Evidence v2 与 Mastery confidence

事件版本、证据数、提示、时间、难度、confidence；修正最低证据合同。

Month 2

状态 CHECK、数值范围；统一 heartbeat、shutdown、metrics 与 error taxonomy。

产出：非法状态进不了库，三个 worker 的运行语义一致。
Month 2-3

隐藏假入口，补诊断式 onboarding

删除未实现分享/付费 affordance；增加与目标 concept 对齐的短 placement。

Month 3

Month 4

产出：课程内容可追溯，生成 KG 可受控沉淀。
