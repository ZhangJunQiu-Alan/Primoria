# AI+教育项目可视化卡片样式规范报告

## 1. 报告目的

本报告基于 Brilliant 课程页面中间区域的可视化卡片样式进行分析，提炼出一套适用于 AI+教育项目的统一视觉规范。  
本规范重点关注 **interactive 卡片、数据可视化卡片、AI 生成图片卡片、概念解释卡片** 等中间可视化内容，不包含页面标题、正文排版、导航栏等外围文字系统。

---

## 2. 核心视觉定位

Brilliant 的中间可视化卡片并不是普通 UI 卡片，也不是装饰性插图，而是一种 **可观察、可点击、可拖拽、可比较的小型学习模型**。

其核心视觉逻辑可以概括为：

> 用简单的视觉对象承载复杂概念，用可操作的组件降低学习理解成本。

因此，在 AI+教育项目中，可视化卡片应被定义为：

> 一个居中的、独立的、可交互或可解释的学习对象。

---

## 3. 可视化卡片的总体原则

### 3.1 One Card, One Concept｜一张卡片只表达一个概念

每张可视化卡片只应该服务一个明确的学习概念，避免在一个卡片中同时表达多个知识点。

**推荐：**

- 一个 AI 生成过程
- 一个数据比较问题
- 一个拖拽排序任务
- 一个概念解释模型
- 一个输入输出关系

**避免：**

- 多个知识点堆叠在同一卡片中
- 同时出现复杂图表、长文本、多个按钮和多个交互任务
- 像 dashboard 一样展示过多信息

---

### 3.2 One Concept, One Action｜一个概念对应一个主要动作

每张卡片应让用户清楚知道自己要做什么。

常见学习动作包括：

- Observe｜观察
- Compare｜比较
- Choose｜选择
- Drag｜拖拽
- Generate｜生成
- Explain｜解释

例如：

- 数据图表卡片：让用户判断哪个数值最大、最接近某个值或变化最明显。
- interactive 卡片：让用户拖动、选择或组合对象。
- AI demo 卡片：让用户输入 prompt 并观察模型输出。
- 概念图卡片：让用户理解输入、处理和输出之间的关系。

---

### 3.3 Make Abstract Things Touchable｜把抽象知识变成可操作物件

Brilliant 的核心优势是将抽象概念转化为具有“物理感”的视觉对象。

例如：

- 词语可以变成 token 卡片。
- 数据可以变成可点击的柱子。
- 概率可以变成卡牌、硬币或抽取装置。
- AI 生成过程可以变成输入框、模型盒子和输出卡片。
- 未知信息可以变成问号区域或虚线框。

这类视觉处理能够让学习过程更像“实验”，而不是单纯阅读。

---

### 3.4 Use Color for Meaning, Not Decoration｜颜色用于表达含义，而不是装饰

颜色应承担功能含义，而不是为了视觉热闹随意使用。

建议颜色功能如下：

| 颜色类型 | 用途 |
|---|---|
| 深青绿色 | interactive 实验台背景、核心操作区域 |
| 薄荷绿色 | 高亮词、token、选中状态 |
| 黑色 | 主体物件、关键词块、强对比内容 |
| 白色 | 卡片、选项、可拖拽物件 |
| 浅灰色 | 边框、空状态、辅助区域 |
| 红色 | 错误、未知、警示、问号 |
| 黄色 / 紫色 / 粉色 / 蓝色 | 分类、图表数据项、不同对象区分 |

---

### 3.5 Keep It Playful but Controlled｜保持有趣，但要克制统一

可视化卡片可以有游戏感，但不应过度装饰。

**推荐：**

- 扁平矢量
- 简单几何形状
- 硬阴影
- 清晰边界
- 低细节物件
- 有限色彩

**避免：**

- 写实照片
- 复杂 3D
- 赛博风
- 强渐变
- 玻璃拟态
- 复杂光影
- 过多装饰元素

---

## 4. 可视化卡片类型

根据 Brilliant 的视觉逻辑，AI+教育项目中的中间可视化内容可以分为四类。

---

# 4.1 Concept Visual Card｜概念解释卡片

## 定义

概念解释卡片用于将抽象概念转化为简洁的视觉模型，适合解释 AI 工作流程、模型差异、输入输出关系、因果关系等内容。

## 典型场景

- LLM 与 SLM 对比
- AI 输入 → 模型处理 → 输出
- 数据来源说明
- 模型无法识别未知词
- 图片生成流程
- prompt 与 response 的关系

## 视觉特征

- 通常不需要明显外部边框
- 白色或透明背景
- 中央放置扁平矢量插图
- 元素数量少
- 标签简短
- 对象之间可以使用箭头、虚线、问号进行连接
- 整体像一个“概念模型图”

## 样式规范

| 属性 | 规范 |
|---|---|
| 背景 | 白色 / 透明 |
| 图形风格 | 扁平矢量、几何化 |
| 细节量 | 低细节 |
| 边线 | 粗线或硬边 |
| 阴影 | 轻微硬阴影 |
| 色彩 | 黑、灰、青绿、黄色为主 |
| 标签 | 短词，不写长句 |

## 设计建议

概念解释卡片应避免做成复杂插画，而应更像“概念积木图”。  
每个对象都应该有明确含义，例如：

- 文件夹 = 数据集
- 放大镜 = 检索 / 搜索
- 方块 = 模型
- 卡片 = 输出结果
- 问号 = 未知 / 不确定
- 箭头 = 流程关系

---

# 4.2 Interactive Stage Card｜互动实验台卡片

## 定义

互动实验台卡片是 Brilliant 风格中最核心的可视化卡片类型。它通过一个明显的操作区域，将学习任务变成可以点击、拖拽、选择或组合的交互实验。

## 典型场景

- 拖拽排序
- 选择正确答案
- 概率模拟
- 卡牌比较
- 分类任务
- 公式拼装
- token 预测
- AI 生成步骤交互

## 视觉特征

- 大面积深青绿色背景
- 圆角矩形容器
- 内部放置可操作物件
- 物件像卡牌、积木、硬币、按钮
- 用户一眼可以识别哪些元素可以点击、拖拽或放置

## 容器规范

| 属性 | 规范 |
|---|---|
| 背景色 | 深青绿色 |
| 圆角 | 18–28px |
| 内边距 | 32–56px |
| 宽度 | 页面主体的 70%–85% |
| 最小高度 | 220–360px |
| 内容布局 | 居中、留白充足 |

## 推荐色值

| 用途 | 色值 |
|---|---|
| Interactive background | `#238A7A` / `#248B7E` |
| Deep object color | `#073B35` / `#062F2C` |
| Light object color | `#F2FAF8` |
| Muted border | `#8BC2BA` |

## 内部物件规范

### 数字卡 / 选项卡

| 属性 | 规范 |
|---|---|
| 背景 | 白色或极浅青白色 |
| 文字 | 黑色 / 深青绿色 |
| 圆角 | 8–12px |
| 边框 | 无或浅灰边框 |
| 阴影 | 底部硬阴影 |
| 字号 | 大、粗 |
| 视觉感受 | 像可以拿起来的小卡片 |

---

### 黑色关键词块

黑色关键词块适合表示 AI token、关键词、分类标签或模型输出词。

| 属性 | 规范 |
|---|---|
| 背景 | 黑色 |
| 文字 | 青绿色 / 薄荷绿色 |
| 形状 | 八边形 / 切角矩形 |
| 字重 | Bold |
| 用途 | token、关键词、分类标签、输出片段 |

---

### Drop Zone 放置区

Drop Zone 是拖拽交互中的目标区域。

| 状态 | 视觉规范 |
|---|---|
| 默认状态 | 浅灰虚线框 |
| 可放置状态 | 青绿色虚线框 + 浅薄荷背景 |
| 正确状态 | 绿色边框 + 浅绿色背景 |
| 错误状态 | 红色边框 + 极浅红背景 |
| 禁用状态 | 浅灰背景 + 灰色文字 |

---

# 4.3 Data Visualization Card｜数据可视化卡片

## 定义

数据可视化卡片用于帮助学生通过图表回答一个明确问题。它不是商业 dashboard，也不是科研图表，而是教学型图表。

## 典型场景

- 读柱状图
- 比较不同类别
- 判断最大值 / 最小值
- 找出接近某个数值的对象
- 观察趋势
- 理解比例关系
- AI 生成数据后的可视化解释

## 视觉特征

- 白色画布
- 浅灰网格线
- 大字号坐标标签
- 低饱和填充色
- 深色描边
- 数据项数量少
- 图表围绕一个问题展开

## 图表规范

| 属性 | 规范 |
|---|---|
| 背景 | 白色 |
| 外边框 | 一般不需要 |
| 网格线 | 极浅灰 |
| 坐标轴 | 浅灰或中灰 |
| 柱子 | 浅色填充 + 深色描边 |
| 标签 | 大号深灰 |
| 图例 | 尽量不用 |
| 数据项数量 | 优先 3–6 项 |

## 柱状图规范

| 属性 | 规范 |
|---|---|
| 填充透明度 | 20%–40% |
| 描边 | 2px |
| 柱子间距 | 较大 |
| 网格线 | `1px #EDEDED` |
| 坐标轴文字 | `#666666` |

## 推荐色值

| 类别 | 填充色 | 描边色 |
|---|---|---|
| Pink | `#F8DCEB` | `#D85AA6` |
| Purple | `#DDD3F2` | `#6B45C8` |
| Blue Grey | `#D5DAE8` | `#1C326D` |
| Yellow | `#FFF1C9` | `#F4B321` |

## 数据图生成原则

AI 生成数据图表时应遵循：

- 每张图只回答一个学习问题
- 优先展示 3–6 个数据项
- 不使用复杂图例
- 不使用 3D 图表
- 不使用渐变
- 不使用复杂阴影
- 不做商业 dashboard 风格
- 坐标轴、网格线和标签保持清晰克制

---

# 4.4 AI Demo / Terminal Card｜AI 演示卡片

## 定义

AI Demo / Terminal Card 用于展示 prompt 输入、模型生成、token 预测、错误提示、重新生成等 AI 相关过程。

## 典型场景

- Prompt 输入
- AI 生成文本
- token 预测演示
- 模型输出对比
- 数据生成过程
- 图片生成过程说明
- 重新生成 response
- 展示模型错误或不确定性

## 视觉特征

- 深色容器
- 类似小型控制台
- 输入内容使用绿色高亮
- 输出内容使用白色等宽字体
- 底部提供重试、重新生成等操作按钮

## 容器规范

| 属性 | 规范 |
|---|---|
| 背景 | `#000000` / `#111111` |
| 顶部栏 | `#1A1A1A` |
| 边框 | 黑色或深灰 |
| 圆角 | 8–12px |
| 字体 | 等宽字体 |
| 高亮色 | 绿色 / 青绿色 |

## 内部元素规范

| 元素 | 规范 |
|---|---|
| 输入 token | 亮绿色 |
| 输出文字 | 白色 |
| 错误提示 | 红色 |
| 分割线 | 深灰 |
| 按钮 | 深灰描边、胶囊形 |

## 操作按钮规范

### Regenerate response

- 透明背景
- 灰色描边
- 胶囊圆角
- 白色文字
- 放在底部右侧

### Start over

- 无背景
- 白色或浅灰文字
- 搭配回转箭头图标
- 放在底部左侧

---

## 5. 通用形状规范

Brilliant 的可视化卡片具有明显的“积木感”和“学习玩具感”。  
形状应简单、硬朗，但不能过于冰冷。

---

### 5.1 圆角矩形

适合用于：

- 互动舞台
- 答案卡片
- 数据容器
- 按钮
- 拖拽区域

规范：

| 类型 | 圆角 |
|---|---|
| 小物件 | 8–12px |
| 中型卡片 | 16–20px |
| 大型舞台 | 20–28px |

---

### 5.2 切角矩形 / 八边形

适合用于：

- 关键词 token
- 概念标签
- AI 生成词块
- 特殊提示块

规范：

| 属性 | 规范 |
|---|---|
| 背景 | 黑色 / 浅灰 |
| 文字 | 高亮色 |
| 切角大小 | 12–20px |
| 圆角 | 不使用普通圆角 |

---

### 5.3 物理道具形状

适合用于：

- 硬币
- 卡牌
- 文件夹
- 浏览器窗口
- 放大镜
- 方块
- 箭头

规范：

- 低细节
- 厚边线
- 少渐变
- 轻微立体厚度
- 硬阴影
- 不使用真实材质

---

## 6. 阴影规范

Brilliant 的阴影不是常见 Material Design 的柔和投影，而是更接近纸片、积木或游戏道具的硬阴影。

## 推荐阴影

```css
box-shadow: 0 6px 0 rgba(0, 0, 0, 0.22);
```

或：

```css
box-shadow: 8px 8px 0 rgba(0, 0, 0, 0.18);
```

## 使用规则

| 对象 | 阴影规范 |
|---|---|
| 大卡片 | 右下硬阴影 |
| 小卡片 | 底部硬阴影 |
| 按钮 | 底部黑色硬阴影 |
| 拖拽物 | 底部 3–6px 硬阴影 |
| 图表 | 通常不使用阴影 |

## 避免使用

- 大面积模糊阴影
- 玻璃拟态阴影
- 蓝紫色发光
- 复杂内阴影
- 过度真实的 3D 阴影

---

## 8. 可交互状态规范

## 8.1 Default｜默认状态

- 白底卡片
- 浅灰边框
- 底部硬阴影
- 无额外强调

## 8.2 Hover｜悬停状态

- 轻微上移 2px
- 边框加深
- 阴影加深
- 鼠标指针变为可点击状态

## 8.3 Selected｜选中状态

- 边框：深青绿色 3px
- 背景：浅薄荷色
- 文字：深青绿色
- 可增加轻微放大反馈

## 8.4 Dragging｜拖拽中

- 卡片略微放大
- 透明度约 90%
- 阴影加深
- 保持清晰边界

## 8.5 Drop Available｜可放置状态

- 虚线框变青绿色
- 背景变浅薄荷色
- 可显示轻量提示图标

## 8.6 Correct｜正确状态

- 边框变绿色
- 背景变浅绿色
- 可添加 check 图标
- 反馈应明确但不过度装饰

## 8.7 Wrong｜错误状态

- 边框变红色
- 背景变极浅红
- 可添加 shake 动效
- 可显示简短错误原因

## 8.8 Disabled｜禁用状态

- 灰色文字
- 浅灰背景
- 无硬阴影或阴影变浅
- 不可点击状态明确

---

## 9. AI 生成图片统一规范

AI 生成图片必须被限制在统一的教育可视化风格中，避免风格漂移。

## 英文 Prompt 规范

```text
Flat educational vector illustration, simple geometric shapes, minimal details, thick outlines, white background, limited color palette, playful but clean, hard shadows, no photorealism, no complex lighting, no gradients, no 3D render, no anime style.
```

## 中文规范

所有 AI 生成图片必须采用扁平教育插图风格：

- 几何化
- 低细节
- 少色彩
- 硬边缘
- 轻微厚度感
- 白色背景
- 清晰学习含义

禁止使用：

- 写实摄影
- 复杂 3D
- 动漫风
- 赛博风
- 强渐变
- 复杂光影
- 无意义装饰背景

---

## 10. AI 生成 Interactive 的规范

AI 生成 interactive 时应遵循以下规则：

- 每个 interactive 只能有一个核心操作
- 交互区域优先使用深青绿色实验台
- 可点击元素必须有清晰边框和硬阴影
- 拖拽物应像卡牌、积木或 token
- 放置区应使用虚线框表示
- 反馈状态必须清楚区分正确、错误、选中、禁用
- 不使用真实照片风元素
- 不使用复杂 3D 元素
- 不在同一卡片内堆叠多个任务

---

## 11. AI 生成数据图表的规范

AI 生成数据图表时应遵循以下规则：

- 每张图只回答一个学习问题
- 优先使用 3–6 个核心数据项
- 图表背景保持白色
- 网格线使用极浅灰
- 柱子使用浅色填充 + 深色描边
- 不使用 3D 图表
- 不使用复杂渐变
- 不使用商业 dashboard 风格
- 坐标标签要大且清晰
- 图例能不用就不用
- 图表必须服务于学习问题，而不是单纯展示数据

---

## 12. AI 生成概念图的规范

AI 生成概念图时应遵循以下规则：

- 使用简单物件表达概念
- 最多使用 3–5 个核心对象
- 对象之间可以使用箭头、虚线、问号连接
- 标签必须简短
- 避免长句说明
- 每个对象都应有明确概念含义
- 优先使用白底和低细节扁平图形
- 避免过度插画化

## 13. 可直接放入产品设计规范的描述

## English Version

```text
Visualization Card Style

The visualization card is a centered, self-contained learning object. It should look like a small interactive model rather than a decorative image or dashboard.

All visualization cards should use a clean white background, simple geometric shapes, bold object boundaries, limited colors, and tactile hard shadows. Interactive cards should use a deep teal stage background with draggable or clickable objects placed inside. Data cards should use minimal teaching-oriented charts with pale fills, darker outlines, light gridlines, and large labels. Concept illustration cards should use flat vector objects, low detail, and short labels.

Avoid photorealistic images, complex 3D rendering, gradients, decorative effects, dense dashboards, and excessive labels. Each card should support one learning action: observe, compare, choose, drag, generate, or explain.
```

## 14. 总结

Brilliant 中间可视化卡片的关键不在于复杂视觉效果，而在于它将抽象学习内容转化为简单、清晰、可操作的视觉对象。

对于 AI+教育项目而言，统一视觉规范的重点不应是制造强烈的“AI 科技感”，而应是建立一种稳定的“学习模型感”。

最终设计方向可以总结为：

> AI 不是生成更炫的内容，而是生成更容易操作和理解的学习模型。

因此，本项目的可视化卡片系统应坚持以下五条原则：

1. 一张卡片只表达一个概念。
2. 一个概念只对应一个主要学习动作。
3. 把抽象知识变成可操作物件。
4. 颜色用于表达含义，而不是装饰。
5. 保持有趣，但必须克制统一。
