# Primoria 个人主页 RPG 游戏化设计说明

> 文档状态：对应当前实现，2026-07-18
>
> 主要入口：`/profile`
>
> 设计主题：知识探索公会
>
> 文档用途：从学习者视角解释已经做好的设计，并提供后续修改索引。运行时代码、测试和 `docs/product/feature_specification.md` 仍是最终事实来源。

## 1. 用户会获得什么体验

用户进入个人主页后，不再只看到一组普通学习统计，而是看到一份“探索者公会档案”。

整个页面回答五个最直观的问题：

1. 我现在是什么阶位，累计了多少 XP？
2. 我当前课程走到哪里，下一节可以学什么？
3. 今天做什么可以保持学习节奏？
4. 我已经获得哪些徽章，还差哪些条件？
5. 我最近取得了什么成果，在哪里看周报和详细统计？

这套系统的定位是“个人学习反馈”，不是能力证明，也不是社交竞争：

- XP 表示经过服务端确认的学习投入和完成行为。
- mastery 表示概念能力证据，两者不会互相替代。
- 完整 RPG 内容只在个人主页展示。
- 课程和测验页只在保存成功后短暂显示 `+XP`、升级或徽章解锁。
- 没有小组任务、公开排行榜、Teach-Back Boss、配对游戏或其他新小游戏。

## 2. 页面全貌

```text
┌───────────────────────────────────────────────────────────────┐
│ 探索者公会档案                                                │
│ [姓名徽记] 用户名 · 公会阶位       [等级星图 · 总 XP · 下一阶] │
│                                  连续天数 / 课程 / 题目 / XP   │
├───────────────────────────────────────────────────────────────┤
│ 公会远征图                                                    │
│ 当前课程：主线 01 ── 复习 02 ── 补救支线 03 ── 主线 04       │
├───────────────────────────────────────────────────────────────┤
│ 每日委托                                                      │
│ [实战训练 0/5] [推进远征 0/1] [成长试炼 0/1]                 │
├───────────────────────────────────────────────────────────────┤
│ 公会徽章：已解锁 3/10                                         │
│ [全部] [远征] [掌握] [坚持] [破局]                            │
│ [已获得徽章] [◇ 未解锁徽章] [◇ 未解锁徽章] ...               │
│ 最近获得                                                      │
```

桌面端将身份铭牌和星图并排，移动端自动变为单列。原有的周报、学习统计和编辑资料入口保留，不会因为 RPG 改版消失。

## 3. 第一屏：探索者身份铭牌与等级星图

### 3.1 身份铭牌

左侧显示：

- 以显示名首字母生成的公会盾徽；
- 用户显示名与邮箱；
- 当前公会阶位；
- 编辑资料入口。

这部分把账号身份和游戏身份合并在同一处，不另外创建角色、职业、装备或复杂属性。

### 3.2 星图与等级进度

右侧使用一条不对称 SVG 星轨表现成长路径：

- 标题显示当前阶位；
- 右上显示累计 XP；
- 星轨下方进度条表示当前阶位到下一阶位的完成比例；
- 文字明确显示“距离下一阶还需多少 XP”；
- 到达最高阶位后改为“已抵达最高阶位”，XP 仍可继续累计。

星轨只做一次描边点亮动画。系统检测到 `prefers-reduced-motion` 时会直接显示完成状态，不播放动画。

### 3.3 第一屏四项数据

| 数据 | 用户看到的含义 | 数据口径 |
| --- | --- | --- |
| 连续天数 | 当前仍有效的连续学习天数 | 每天完成任意一项每日任务即可延续 |
| 完成 lesson | 已完成的课程节数 | 来自真实 lesson 完成记录 |
| 练习题 | 已提交的课程测验题目 | 来自课程学习事件 |
| 总 XP | 新系统上线后获得的全部 XP | 来自只增不改的服务端 XP 账本 |

## 4. 八个公会阶位

| 阶位 | 累计 XP 门槛 | 用户感受 |
| --- | ---: | --- |
| 见习探索者 | 0 | 刚加入公会，开始第一段学习旅程 |
| 寻路者 | 200 | 已形成最初的学习路径 |
| 开拓者 | 600 | 能持续推进多个学习节点 |
| 符文研习者 | 1,400 | 开始积累稳定的理解与练习证据 |
| 典籍守卫 | 2,800 | 已保持较长时间的学习投入 |
| 星图绘制师 | 5,000 | 能跨课程看见自己的成长轨迹 |
| 大贤者 | 8,000 | 完成大量经过验证的学习行动 |
| 原境传承者 | 12,000 | 首版最高阶位，XP 仍继续累计 |

等级只由累计 XP 推导，浏览器不能直接修改等级。

## 5. XP 规则

### 5.1 基础 XP

| 学习行为 | 奖励 | 限制 |
| --- | ---: | --- |
| 首次有效提交一个测验块 | 每题 8 XP | 只计算游戏化开始时间之后的首次提交 |
| 刷新该测验块的个人最佳成绩 | 每题 2 XP | 同一用户当地自然日只奖励第一次刷新 |
| 首次完成一节 lesson | 40 XP | 同一 lesson 永远只奖励一次 |

示例：一个 5 题测验块第一次提交可获得 `5 × 8 = 40 XP`。第二天把个人最佳成绩从 3/5 提高到 5/5，可获得 `5 × 2 = 10 XP`。

### 5.2 明确不给 XP 的行为

- 与 Tutor 聊天；
- 生成课程或生成 lesson；
- 打开、浏览或刷新页面；
- 重复完成同一节 lesson；
- 重复提交但没有刷新个人最佳；
- 在同一天第二次或更多次刷新同一测验块的最佳成绩；
- 只在客户端出现、但没有成功保存到服务端的答题结果。

这个边界避免“刷页面、刷聊天、网络重试”变成获得 XP 的方法。

## 6. 公会远征图

### 6.1 课程如何被选中

系统按课程最近更新时间排序，优先显示最近更新的未完成课程；如果没有未完成课程，则显示列表中的最近课程。没有课程时显示空状态，引导用户先从学习目标创建课程。

### 6.2 节点顺序和类型

课程节点严格按 `sortKey` 排列，三类 lesson 使用不同的任务语义：

| lesson role | 页面名称 | 含义 |
| --- | --- | --- |
| `new` | 主线 | 学习新的课程内容 |
| `review` | 复习 | 重新巩固已有内容 |
| `remediation` | 补救支线 | 针对薄弱证据进行补救 |

### 6.3 两种状态分开表达

远征图不会把“课程内容是否生成好”和“用户是否学完”混在一起：

- `未生成`：课程计划中已有这个节点，但内容还没准备；
- `准备中`：后台正在生成内容；
- `可进入`：内容已生成，可以点击；
- `已完成`：用户已经完成这一节点；
- `当前任务`：前面的节点已完成，当前节点是自然的下一步。

只有内容已生成的节点提供课程链接。计划中和准备中的节点保持可见，但不会制造人为等级锁，也不会假装可以进入。

## 7. 三项每日委托

| 每日委托 | 达成条件 | 奖励 | 进度来源 |
| --- | --- | ---: | --- |
| 实战训练 | 当天完成 5 道不同题目 | 20 XP | 去重后的课程 quiz 学习事件 |
| 推进远征 | 当天完成 1 节 lesson | 30 XP | `lesson.completed` 事件 |
| 成长试炼 | 完成复习/补救 lesson、刷新测验最佳成绩、或新掌握一个概念，任一达成 | 40 XP | 课程完成、XP 账本或 mastery 状态转换 |

设计意图：

- 实战训练鼓励真实练习，而不是重复点同一道题；
- 推进远征鼓励完成一个完整的小学习步骤；
- 成长试炼奖励“比之前更好”或“针对薄弱点做修复”，而不只是堆数量。

每项任务每天只完成一次、只奖励一次。卡片同时显示当前进度、目标和 XP 奖励。完成后使用非颜色样式变化标明状态。

## 8. 连续学习与归队

连续学习按用户的当地自然日计算：

1. 当天完成三项任务中的任意一项，就算当天有效学习。
2. 上一次有效学习是昨天，当前连续天数加 1。
3. 上一次有效学习就是今天，重复完成其他任务不会重复增加连续天数。
4. 中间间隔超过一天后，下次完成任务时从 1 天重新开始。
5. 两次有效任务完成日期相差至少 7 个自然日，再次完成任务会解锁“归队者”。

页面会显示当前连续天数和历史最长连续天数。用户浏览器的 IANA 时区会自动同步到设置；如果暂时没有时区，服务端使用 UTC，避免由浏览器随意提交日期造成重复奖励。

## 9. 十枚公会徽章

徽章墙包含总完成进度、分类筛选、已解锁/未解锁网格、解锁要求、XP 标签、获得日期和最近获得记录。

| 徽章 | 分类 | 解锁条件 | 额外 XP |
| --- | --- | --- | ---: |
| 初次远征 | 远征 | 完成第一节 lesson | 50 |
| 任务线完成 | 远征 | 完成第一门课程 | 150 |
| 初识奥义 | 掌握 | 首次掌握一个概念 | 0 |
| 十项奥义 | 掌握 | 掌握 10 个不同概念 | 0 |
| 破局者 | 破局 | 完成第一节补救 lesson | 75 |
| 无瑕试炼 | 掌握 | 在至少 3 道题的测验中获得满分 | 0 |
| 三日守火 | 坚持 | 连续学习 3 天 | 50 |
| 七日长明 | 坚持 | 连续学习 7 天 | 100 |
| 归队者 | 破局 | 与上次有效学习相隔至少 7 个自然日后重新完成每日任务 | 75 |
| 融会贯通 | 掌握 | 至少 3 道题、覆盖至少 2 个概念的测验满分 | 0 |

筛选项固定为：全部、远征、掌握、坚持、破局。未解锁徽章仍显示名称和要求，并使用 `◇ 未解锁` 文字，不只依赖灰色或透明度表达锁定状态。

徽章使用 Primoria 自己的盾形 SVG 纹章：

- 远征：勾选/路径符号；
- 掌握：符文/三角符号；
- 坚持：火焰符号；
- 破局：十字路径/回归符号；
- 青铜、白银、黄金稀有度使用不同边框，但文字仍会明确显示稀有度。

## 10. mastery 与 XP 为什么必须分开

用户可能获得很多 XP，但这不等于已经掌握全部概念。例如，持续完成课程和复习本身值得获得进度反馈，但掌握状态必须有足够的答题证据。

当前 mastery 最低规则：

- 至少有 3 道属于该概念的题目证据；
- 正确率达到 80%；
- `1/1` 或 `2/2` 即使全对，也不会进入 `mastered`；
- mastery 状态只有真正变化时才产生转换事件和掌握类徽章判定。

因此页面上的三种数据分别回答不同问题：

| 数据 | 回答的问题 |
| --- | --- |
| XP / 等级 / 连续学习 | 我投入并完成了多少经过验证的学习行动？ |
| mastery | 我对哪些概念已经有足够的能力证据？ |
| learner facts | 系统知道哪些有助于个性化教学的稳定背景、偏好、目标或学习卡点？ |

## 11. 课程中的奖励提示

测验提交成功后，课程组件可以短暂显示：

- 本次新增 `+XP`；
- 当前总 XP；
- 从哪个阶位升到哪个阶位；
- 新解锁的徽章；
- 本次完成的每日任务。

交互规则：

- 只使用服务端成功响应中的奖励结果；
- 相同 `submissionId` 重放时，本次 `xpAwarded` 为 0，不重复弹出奖励；
- 相同 `submissionId` 如果携带不同答案，接口返回冲突；
- 保存失败时保留本地答题反馈，但明确提示“进度未保存”；
- 保存失败时绝不显示 XP、升级或徽章解锁。

由后台 mastery Worker 解锁的徽章不会在课程页轮询弹出；用户下次打开个人主页时，会在“最近获得”中看到。

## 12. 新旧用户的起点

游戏化系统上线后，所有已有用户也从 `0 XP`、见习探索者开始。

系统为每个用户记录 `player_progress.startedAt`：

- 之前完成过的课程、测验和 mastery 不回算；
- 之前的历史仍保留在原学习记录和统计中；
- 只有起点之后的可信学习事件能进入 XP、每日任务、连续学习和徽章；
- 这样可以让所有用户在同一套明确规则下开始，也避免一次迁移突然解锁大量徽章。

## 13. 视觉系统

### 13.1 色彩

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| Guild Ink | `#17130F` | 深色文字、盾徽细节、沉稳底色 |
| Parchment | `#FFF7E6` | 羊皮纸感亮色、深色区文字 |
| Midnight Atlas | `#20324A` | 英雄区和星图主背景 |
| Verdigris | `#357568` | 探索、恢复、辅助发光 |
| Quest Gold | `#C58A2A` | XP、进度、徽记和关键奖励 |
| Ember | `#B85C38` | 青铜稀有度、破局和强调 |

### 13.2 字体

- 大标题和阶位：`Palatino Linotype / Songti SC`，形成典籍与公会感；
- 正文：沿用 `Avenir Next / PingFang SC` 系统字体；
- XP、编号、标签：等宽字体，强化任务记录和数值感；
- 不增加新的网络字体或运行时字体依赖。

### 13.3 视觉语言

- 深色公会星图作为唯一主视觉，不把原来的暖色卡片简单换皮；
- 每日委托使用卷轴/任务纸张感，但保持清晰可读；
- 徽章是盾形公会纹章，不复制 Studyield 的品牌图形；
- 主线、复习和补救支线有不同视觉信号，同时保留文字标签；
- 所有关键状态都用文字和图形共同表达，不能只依赖颜色。

## 14. 响应式与无障碍

- 移动端英雄区、任务节点、每日委托、徽章网格全部变为单列；
- 徽章筛选按钮可通过键盘操作，并有明确焦点状态；
- 锁定状态包含 `◇ 未解锁` 文案；
- 课程节点链接包含可读的 `aria-label`；
- 星图属于装饰，不干扰屏幕阅读器；
- 动效遵守 `prefers-reduced-motion`；
- 奖励提示使用 `aria-live`，让辅助技术能够读出新增奖励；
- 中英文界面使用同一套结构和规则，只切换文案。

## 15. 数据可信与防重复奖励

从用户角度，最重要的承诺是：一次真实学习只算一次，网络重试不会多算，保存失败也不会假装成功。

实现上由四组数据负责：

| 数据 | 作用 |
| --- | --- |
| `player_progress` | 保存游戏化起点、总 XP、当前/最长连续天数和最后任务日期 |
| `xp_awards` | 只增不改的每笔 XP 账本 |
| `daily_quest_completions` | 保存用户在某个当地日期完成的任务 |
| `achievement_unlocks` | 保存每枚徽章的首次解锁时间 |

每笔 XP 都带“用户 + 规则 + 去重键”。只有成功插入新的账本记录，系统才会增加总 XP。这样可以抵抗：

- 连点提交；
- 浏览器自动重试；
- 相同请求重放；
- 后台 Worker 重跑；
- 同一 lesson 重复完成；
- 同一日期重复领取每日任务。

## 16. 后续修改入口

后续改设计时，应先明确是“经济规则”“视觉/交互”“文案”还是“数据契约”，不要只改页面显示造成前后端不一致。

| 想修改的内容 | 主要文件 | 修改提醒 |
| --- | --- | --- |
| 阶位名称和 XP 门槛 | `apps/web/src/lib/gamification/catalog.ts` | 同步中英文名称、边界测试和本文档 |
| 每日任务目标与奖励 | `apps/web/src/lib/gamification/catalog.ts` | 同步服务端判定、测试和文案 |
| 徽章条件、分类、稀有度、奖励 | `apps/web/src/lib/gamification/catalog.ts`、`store.ts` | 条件和展示必须同步，新增 code 需要迁移/测试评估 |
| 测验、lesson、任务和徽章落账 | `apps/web/src/lib/gamification/store.ts` | 必须保持事务和去重键，不允许客户端直接加 XP |
| 时区与自然日算法 | `apps/web/src/lib/gamification/time.ts` | 重点测试跨日、夏令时和 UTC fallback |
| mastery 最低证据 | `apps/web/src/lib/mastery/rules.ts` | 这是能力规则，不应为了加快升级而放宽 |
| 个人主页首屏和星图 | `apps/web/src/app/profile/page.tsx` | 保留服务端主体数据加载 |
| 任务图、每日委托、徽章筛选 | `apps/web/src/components/profile/gamification-hub.tsx` | 客户端只负责筛选和时区同步 |
| 奖励提示 | `apps/web/src/components/course/course-block-quiz.tsx` | 只能根据成功的服务端响应显示 |
| 色彩、布局、响应式和动效 | `apps/web/src/app/globals.css` | 同步 reduced-motion 与移动端单列 |
| 中英文文案 | `apps/web/src/lib/i18n/dictionaries.ts` | 中英文结构必须保持一致 |
| 数据表 | `apps/web/src/lib/db/schema.ts`、`apps/web/drizzle/0047_slim_earthquake.sql` | 迁移保持纯新增和向后兼容 |
| 产品口径 | `README.md`、`AGENTS.md`、`CLAUDE.md`、`docs/*` | XP、mastery、个人/社交边界必须一致 |

## 17. 修改前需要回答的五个问题

每次调整游戏化内容前，建议先填写：

1. 这项变化奖励的是“真实学习行为”还是只是“页面活跃”？
2. 它会不会把 XP 错当成 mastery？
3. 用户能否通过刷新、重试、重复提交或客户端修改重复领取？
4. 它应该只出现在个人主页，还是只需要课程中的短暂提示？
5. 是否无意中引入排行榜、小组竞争或新小游戏，超出当前个人学习范围？

## 18. 用户验收场景

### 场景 A：第一次进入

- 看到见习探索者、0 XP、0 天连续学习；
- 旧课程和旧测验不会突然带来 XP 或徽章；
- 有课程时看见课程任务线，无课程时看见明确空状态；
- 徽章墙显示 0/10，并能查看所有解锁要求。

### 场景 B：第一次完成 5 题测验并完成 lesson

- 获得首次测验 `40 XP`；
- 首次完成 lesson 获得 `40 XP`；
- 解锁“初次远征”并获得 `50 XP`；
- 完成“实战训练”获得 `20 XP`；
- 完成“推进远征”获得 `30 XP`；
- 如果该 lesson 是复习或补救，还可能完成“成长试炼”；
- 课程页只显示一次服务端确认的奖励提示。

### 场景 C：重复提交

- 相同提交重放不重复加 XP；
- 同一个测验块普通重复提交为 0 XP；
- 刷新个人最佳时按规则奖励，但同日第二次刷新不再给改善 XP；
- 保存失败时不出现任何奖励提示。

### 场景 D：连续学习

- 今天完成任意每日任务，连续天数记为 1；
- 明天再次完成任意每日任务，连续天数变为 2；
- 同一天完成三项任务只增加一次连续天数；
- 间隔超过一天再回来，从 1 开始；
- 与上次有效日期相差至少 7 天，完成任务后解锁“归队者”。

### 场景 E：掌握概念

- 1/1 或 2/2 全对不会错误进入 `mastered`；
- 至少 3 题且正确率达到 80% 才能进入 `mastered`；
- 首次真实进入 mastered 解锁“初识奥义”；
- Worker 重跑不会重复解锁或重复奖励。

### 场景 F：移动端与辅助功能

- 所有区域为单列，无横向挤压；
- 键盘可以切换徽章分类；
- 锁定状态不依赖颜色；
- 减少动态效果偏好开启后，星图不播放描边动画；
- 奖励提示可被辅助技术读取。

## 19. 当前不做的内容

以下内容不是遗漏，而是明确暂缓：

- 小组学习和小组任务；
- 公开排行榜、好友排名或班级排名；
- Teach-Back Boss；
- 配对小游戏；
- 角色装备、道具、金币、商城；
- 通过聊天次数、浏览时长或生成课程获得 XP；
- 用等级锁住课程内容；
- 把历史学习记录回算成 XP；
- 在 `/stats` 或 `/weekly-report` 再复制一套 RPG 面板。
