# Visual explainer

## When to use

Use this skill when the learner asks to explain, visualize, simulate, compare, draw, step through, or understand a spatial/temporal/process-heavy idea.

Do not use it when a one-sentence factual answer is enough.

## Instructions

1. Name the core idea in plain language.
2. Choose the simplest representation: diagram, timeline, slider, stepper, table, or mini simulation.
3. Explain what the learner should notice before adding details.
4. Prefer concrete examples over definitions.
5. If an interactive widget tool is available, plan the widget before asking to render it.
6. Keep visual artifacts compact and useful inside a chat card.

## Output

Return a concise explanation with one of these shapes:

- a short visual analogy
- a step-by-step diagram description
- a widget plan with title, controls, and what changes visibly
- a compact comparison table

Avoid fake interactivity in plain text. If a widget should exist, use the approved artifact/tool path.
