# 7. Building and Development Tools

Last updated: 2026-04-05

## Objective

Explain what tools and libraries are used, and why they are appropriate for this project.

## Core Stack

| Category | Tools/Libraries | Usage in project |
| --- | --- | --- |
| Language/runtime | TypeScript, Node.js | Frontend app and scripts |
| Frontend framework | React 19 | Unified learner + builder web app |
| Build tooling | Vite | Fast local dev and production bundling |
| State/data | Redux Toolkit, React Query | UI state and async data flow |
| Validation/schema | Zod (`@primoria/schema`) | Canonical data contract and migration safety |
| Backend platform | Supabase (Auth, Postgres, RLS, RPC, Edge Functions) | Authentication, storage, and business data |
| Testing (unit/component) | Vitest, Testing Library | Component and logic verification |
| Testing (e2e/smoke) | Playwright, script-based smoke checks | Browser-level and release-level validation |
| External test harness | Python pytest (`external-tests`) | API-level user story checks |
| CI/CD | GitHub Actions workflows | Automated test and deploy pipeline |
| Deployment | Cloudflare Pages and GitHub Pages workflow paths | Preview/production/static deployment routes |
| Design/planning | Miro board | Backlog, story mapping, estimation, task decomposition, velocity |

## Why These Tools Were Chosen

1. React + Vite gives rapid iteration speed and strong ecosystem support.
2. Supabase reduces backend setup overhead while supporting production-grade auth/data patterns.
3. Zod schema package keeps data validation and compatibility centralized.
4. GitHub Actions provides transparent, reproducible CI/CD suitable for assignment evidence.
5. Mixed test strategy (unit + e2e + external API tests) provides practical coverage breadth.

## Build and Run Commands

```bash
pnpm install
pnpm --filter @primoria/viewer-react dev
pnpm --filter @primoria/viewer-react build
pnpm --filter @primoria/viewer-react test
```
