## Objective

This page summarizes architectural, database, and interface design decisions for major system components, with links to detailed docs and required design artifacts.

## Major Components

| Component | Responsibility | Key technology | Why this design |
| --- | --- | --- | --- |
| Viewer React app | Learner flows and Builder workspace in one frontend | React 19, TypeScript, Vite, React Router, React Query, Redux Toolkit | Single SPA reduces duplication, improves deployment consistency |
| Shared schema package | Canonical course model and migration compatibility | `@primoria/schema`, Zod | Keeps Builder and learner runtime aligned |
| Supabase backend | Auth, database, RLS, RPC, edge functions | PostgreSQL, Supabase Auth, RLS, Edge Functions | Fast backend iteration with built-in auth and policy controls |
| CI/CD workflows | Build, test, preview, production deployment | GitHub Actions, Cloudflare Pages/GitHub Pages | Automated quality and release gates |

## Design Justifications (Summary)

1. Unified frontend reduced cross-app handoff complexity and improved maintainability.
2. Shared schema plus migration helpers protects backward compatibility of course content.
3. Supabase provides reliable auth/data foundations with rapid iteration speed.
4. Responsive dashboard layout supports assignment requirement for practical multi-device UI behavior.
