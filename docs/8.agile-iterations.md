# 8. Agile Iterations and Team Process

Last updated: 2026-04-05

## Objective

Document agile planning and execution evidence across iterations.

## Iteration 1 (Miro Evidence)

### Week 1: Backlog ideation

- Team generated multiple concepts.
- Selected direction: learning hub for university students.

### Week 2: User stories, priority, and estimation

- User stories defined and ranked by priority.
- Multi-estimator approach used (Kieran, Zic, Christ, Alan).
- Final estimates agreed per story.

### Week 4: Breakdown into implementable tasks

- Stories decomposed into smaller tasks.
- Per-task estimated time added.
- Work items marked as `Done` or `In-progress`.

### Iteration 1 retrospective and velocity

- Retrospective note: improve user-story quality and estimation accuracy.
- Velocity recorded on board:
  - `E1 = 8 * 4 = 32`
  - `A1 = 20 * 4 = 80`
  - `V1 = E1 / A1 = 32 / 80 = 0.4`

## Iteration 2 (Miro Evidence)

### Week 5 to Week 7: continuing execution

- High-priority story remained active with detailed task flow.
- Work status still visible as `In-progress` in screenshots.

### Iteration 2 velocity

- Board formula:
  - `E2 = 19 * 4 = 76`
  - `V2 = E2 / E1 * V1 = 76 / 32 * 0.4 = 0.95`

Interpretation:
- Team delivery performance improved substantially between Iteration 1 and Iteration 2.

## Agile Practices Applied

1. Backlog generation and prioritization.
2. User-story based planning.
3. Team-based estimation.
4. Iterative decomposition of stories into tasks.
5. Progress visibility (`Done`/`In-progress`).
6. Retrospective feedback loop.
7. Velocity tracking for planning calibration.

## Improvements for Next Iteration

1. Define each story with explicit acceptance criteria before implementation starts.
2. Link every story to issue IDs and test cases.
3. Run mid-iteration review to reduce late re-estimation.
4. Maintain iteration log in repo (not only on board) for assessment traceability.
