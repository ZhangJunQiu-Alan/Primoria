# 主 Tutor 用户意图与路由边界

状态：当前产品意图分类参考，2026-07。实际优先级以
`apps/agent/src/prompts.mjs` 和工具 schema 为准。

## 1. 建课与学习路径

典型表达：

- “我想学牛顿力学”
- “从头教我微积分”
- “帮我建一门关于法国大革命的课程”

主 Tutor 必须调用 `position_learning_goal`。Agent 只表达目标；Web 负责 KG
定位/生成图 fallback、建课、持久化和 lesson job。不要从聊天里直接写课程。

课程详情模式优先于普通建课规则：用户在现有课程中要求解释、总结或继续
当前内容时，应使用当前 course/lesson/visible blocks 上下文，不应新建课程。

## 2. 普通概念讲解

典型表达：

- “解释一下复利是什么”
- “为什么链式法则要乘内层导数？”
- “给我一个直观比喻”

如果不需要 UI、课程或工具，直接回答。回答策略受知识背景、Tutor style 和
有效 learner facts 影响。事实是个性化数据，不能覆盖系统规则或主题必学内容。

## 3. 交互式可视化

路由优先级：

1. Catalog 有贴切组件：`open_interactive_component`；
2. 无 Catalog 组件但存在结构化 renderer：使用对应 chart/diagram/physics/
   algorithm/math/3D/wave/graph/molecule 工具；
3. 其余自定义可视化：`plan_visualization` 后立即调用
   `widgetRenderer`/`stemRenderer`。

后续“调大一点”“换成凹透镜”“再快一点”等调整，继续使用相同
componentId 调用 `open_interactive_component`。Web 根据卡片当前 config
生成最小 patch。

Catalog 覆盖 STEM、人文、文学、语言、社会科学、地理、艺术、音乐和心理学，
不能因为请求不是 STEM 就自动走 sandbox。

## 4. 临时测验与课程测验

- 主 Tutor 首页中的宽泛“考我/出练习”请求按学习目标处理，进入
  `position_learning_goal` 建课流程。
- 明确处于 Course Detail Mode 时，临时练习调用 `render_chat_quiz`，直接在
  聊天中出现，不创建课程 block，也不更新 mastery。
- 课程 lesson 内的 quiz block 通过课程 API 提交，记录幂等 quiz attempt、
  learning event，并成为 mastery/诊断证据。

不要把概念 mastery 和 learner facts 混为一谈：Quiz 证据更新 mastery；
Extractor 才从一段学习事件中提炼长期偏好、背景或学习卡点。

## 5. 代码讲解与运行

- 代码解释可以返回结构化 code artifact。
- 课程 code block 支持浏览器内编辑/运行 Python 或 JavaScript。
- 只有代码适配主题或明确代码意图才生成 code block；“实现共同富裕”等
  非编程语义不能触发代码。

## 6. 个性化与记忆

已实现入口：

- Onboarding 保存学习目标、知识背景和 Tutor style，并同步为 facts。
- 课程完成后的 Extractor 产生 evidence-backed facts。
- Settings/Facts 展示 active facts，用户可以 dismiss 错误或不希望继续使用的事实。

当前聊天里没有通用“直接写/删任意 fact”的 Agent 工具。因此：

- “记住我是高中生”可在对话中影响当次交流，但长期存储应通过明确产品入口
  或后续受控记忆工具，不能假装已持久化；
- “忘掉这条信息”应引导用户到 Settings/Facts 完成可审计删除/忽略；
- 纠正事实不能只在自然语言里口头承诺成功。

## 7. 学习状态与进度查询

用户可能询问：

- 当前课程和 lesson；
- 哪些概念薄弱；
- 最近学习活动；
- weekly report 或课程进度；
- 当前 XP、公会等级、每日任务、连续学习和已获得徽章。

产品已有课程、mastery、learning events、Stats、Weekly Report 和个人主页公会
进度数据面。完整 RPG 信息只在 `/profile` 展示；课程测验只在服务端成功保存后
短暂提示 `+XP`、升级或徽章解锁。XP 表示经过验证的学习投入与完成，不等于
mastery；不要因为 XP 高就声称用户已掌握某个概念。

Tutor 回答只能使用实际注入/可读取的上下文；没有工具或数据时应明确范围，
不能编造完整学习历史。

## 8. 情绪与动机支持

“太难了”“我学不会”“考前焦虑”等首先需要简短承接，再把当前教学动作
缩小：降阶解释、换类比、做一题检查或拆分目标。情绪表达本身不能自动写入
长期事实；只有可复用、证据充分的稳定特征才由 Extractor 处理。

## 9. 越界、护栏与尚未支持

- 作业/考试答案请求应维持教学与诚信边界，优先解释思路和检查理解。
- 非学习工具化请求不应触发建课或可视化工具。
- KG 覆盖外学习目标可以走 generated graph；KG 基础设施故障不能伪装成
  coverage miss。
- 当前没有通用课堂/教师协作、用户创建 Agent、Agent marketplace 或系统级
  跨用户记忆。
- 当前没有小组任务、公开排行榜、Teach-Back Boss、配对游戏或其他新小游戏。
- 多模态附件有基础处理，但“完整多模态学习输入”仍不是已完成产品能力。
