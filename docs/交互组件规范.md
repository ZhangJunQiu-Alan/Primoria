# 声明式交互组件规范

状态：生产运行时规范、组件任务书和入库审核标准，2026-07。

本规范适用于 Primoria 主 Tutor 已接入的全学科声明式组件。旧的 QA
目录仅保留为隔离评测入口，不再是组件代码或生产架构的事实源。

## 1. 生产架构

Primoria 的教学可视化采用“声明式 Catalog 优先、结构化渲染与 sandbox
兜底”的混合架构。

主 Tutor 路径：

```text
学生请求
→ 主模型读取精简 Catalog
→ 命中：调用 open_interactive_component(component_id, request)
→ 浏览器 InteractiveComponentCard
→ POST /api/interactive-component（带登录态）
→ create：生成完整 config
  adjust：生成最小 patch 并合并到当前 config
→ Zod 校验完整对象
→ 对应 React Widget 渲染
```

当 Catalog 没有贴切组件时，Agent 继续选择图表、Mermaid、物理、算法、
数学、3D、波、图、分子等结构化 renderer；仍不匹配时才走
`plan_visualization → widgetRenderer` sandbox HTML 兜底。

生产 Stage 1 是主模型选择 `open_interactive_component` 这个工具，而不是
额外调用一个 `select_component` 工具。`selectInteractiveComponent` 仅用于
QA 路由和固定评测集，方便单独回归 Stage 1。

两条硬原则：

- 质量来自预先工程化的组合：公式、计算、图形和版式由组件锁定，LLM
  只配置教学参数。
- 颗粒度是“一个教学场景一个组件”：config 只出现学生/老师会说出口的
  教学概念，禁止坐标、颜色、尺寸等视觉实现字段。

## 3. 新增组件的七件套

新增组件必须同时完成：

1. 在 `catalog.v1.json` 增加完整双语条目、JSON Schema、默认 config、
   patchHints、降级条件与示例。
2. 在 `apps/web/src/lib/interactive/components/<name>.ts` 定义完整/patch
   Zod schema、默认 config、纯计算函数、`ImplementedComponent` 元数据。
3. 加入 Web `COMPONENT_REGISTRY`。
4. 加入共享 `interactive-catalog.mjs`，保持 componentId、名称和一行描述
   与 Registry 一致，使 Agent 能路由。
5. 实现 `apps/web/src/components/generative-ui/interactive/<name>.tsx`。
6. 加入 `WIDGETS` map，并通过 schema 恢复强类型 config。
7. 增加组件单测、Catalog/Registry/Widget 同步验证，并按需要扩充固定
   路由评测集。

不要为声明式组件新增 `TutorArtifact`。`open_interactive_component` 是前端
工具信号，组件实例和 config 由浏览器/Web 管理。

## 4. Config Schema 规则

- 所有字段必须有 `.default()`；数值必须有 `.min()`/`.max()`。
- Patch schema 与完整 schema 字段一致并全部可选；每个字段必须能独立修改。
- 字段名使用教学语义 camelCase，如 `focalLength`，不用 `f`、`x1`。
- 枚举优先于互相冲突的布尔组合。
- 禁止 `z.any()`、开放式 `z.unknown()` 字段和视觉实现字段。
- 字段通常控制在 3–7 个；超过时先重新评估场景颗粒度。
- create 输出完整 config；adjust 只输出最小 patch。Patch 合并后必须重新
  通过完整 schema，不能让局部合法产生全局非法状态。

## 5. 计算层规则

- 教学计算写成组件模块内的纯函数，React 只负责展示和事件绑定。
- 不允许隐式随机；确需随机时传显式 seed 并保证可复现。
- 除零、定义域外、`u=f` 等奇点返回显式状态，禁止 NaN/Infinity 进入渲染。
- 数值断言必须覆盖代表点、边界和奇点；浮点使用 `toBeCloseTo`。
- 人文/社会科学组件也需要“计算层”：例如失效引用过滤、因果入出度、
  证据归属和政策维度聚合，不能把所有逻辑塞进 JSX。

## 6. React Widget 规则

Props 固定为：

```ts
{ config: XConfig; onChange: (next: XConfig) => void }
```

- 学生能调整的教学参数必须通过 `onChange` 回写同一个 config；拖拽、
  滑块和自然语言 patch 必须共享状态源。
- 播放/暂停、当前选中项、未持久化草稿标注等瞬时 UI 可使用局部 state。
- SVG 使用固定 `viewBox`、`width: 100%` 和明确世界坐标映射。
- 颜色只从 `WIDGET_COLORS` 取。该 Palette 绑定生产语义 token，并为隔离
  QA 提供 fallback；禁止组件新增裸 hex。
- 禁止网络请求、DB、未经批准的依赖和 `dangerouslySetInnerHTML`。
- 可交互控件必须可聚焦、有 label；图形需要合适的 role/aria-label。
- 合法参数全域不得产生版式爆炸。极值应动态缩放或裁剪并提示。
- UI 固定文案必须通过 `useT()` 读取中英文字典，不能在组件内硬编码中文。

## 7. 内容型组件规则

`general.timeline-causality` 和 `humanities.source-comparison` 使用
`AI_MODEL_CONTENT`（若配置），否则使用默认模型，绝不降到
`AI_MODEL_FAST`。其他组件 Stage 2 可使用 fast tier。

时间线、史料比较、细读等内容不得把模型输出包装成权威原始资料：

- 展示“AI 生成学习辅助内容”的核验提醒；
- 让学生区分时间先后与直接因果；
- 史料并列不代表同等可靠；
- 政策权重只帮助提问，不自动宣布赢家；
- 引用关系必须验证 id，失效引用过滤并显式计数；
- 支持学生标注、质疑和待核验记录。

## 8. SchemaDoc 与 PatchHints

- `schemaDoc` 用中文逐字段列出含义、单位、范围、默认值，与 Zod 一致。
- `patchHints` 至少覆盖两条常见口语约定，如“再快一点”“焦点以内”。
- 模糊相对调整必须写明比例/步长和 clamp 规则，避免模型随意猜值。
- 文本内容字段 create 时必须生成具体教学内容，禁止“待补充”占位。
- Catalog 的中英文 hints、组件元数据和评测 prompt 应保持语义一致。

## 9. 测试与入库门禁

每个组件至少覆盖：

1. 空对象得到完整默认 config；越界/非法枚举被拒绝；
2. 单字段 patch 通过，越界 patch 被拒绝；
3. 规格中的代表数值和奇点；
4. 任意引用过滤和安全边界；
5. 默认 config 可以 SSR；
6. Registry、共享 Agent Catalog、JSON Catalog、Widget Map 同步。

一票否决：

- `z.any()`/视觉字段/无界数值；
- 教学计算只写在 JSX；
- 网络、DB、未批准依赖、`dangerouslySetInnerHTML`；
- 学生调参没有写回 config；
- componentId 在任何一层漂移；
- typecheck、lint、unit、Catalog 校验未通过。

验证命令：

```bash
pnpm --filter @primoria/web typecheck
pnpm lint
pnpm --filter @primoria/web test
pnpm catalog:validate
pnpm --filter @primoria/web test:interactive-routing
```

更改 Catalog、路由 prompt 或模型后，还要运行真实模型评测：

```bash
pnpm --filter @primoria/web eval:interactive-routing
```

主链路上线门禁是登录态人工验证：主 Tutor 请求命中
`open_interactive_component`、卡片渲染成功、后续口语调整返回 patch。

## 10. 当前 Catalog

当前 19 个组件：

- 数学/科学/计算：`physics.lens-imaging`、`chem.acid-base-titration`、
  `physics.wave-superposition`、`cs.sorting-steps`、
  `math.function-explorer`、`math.angle-measure`。
- 通用/人文/语言：`general.timeline-causality`、
  `general.process-sequence`、`humanities.source-comparison`、
  `humanities.argument-map`、`literature.narrative-arc`、
  `literature.character-relationships`、`literature.close-reading`、
  `language.sentence-structure`。
- 社会科学/地理/艺术：`social.policy-tradeoff`、
  `geography.climate-comparison`、`arts.color-harmony`、
  `music.rhythm-pattern`、`psychology.experiment-design`。

不按 KG concept 数量机械扩建。下一批从真实数据决定：内部分析页按
sandbox topic 聚类目录未命中，并按 componentId 计算 interactive 成功率。
建议先积累 2–4 周流量，优先做高需求、可工程化且能产生真实学生操作的
场景；在此之前优先深化 timeline/source-comparison 等人文交互。
