# 声明式交互组件规范(任务书 + 入库审核标准)

本文档是交给组件实现 Agent 的完整任务书,同时是入库审核(由主导 Agent 执行)的评分标准。实现 Agent 应通读全文后再动工;任何与本文冲突的自行发挥都会在审核时被打回。

## 1. 架构背景(必读,一屏)

Primoria 的教学可视化采用**声明式为主、沙箱为辅**的混合渲染:LLM 只输出极简 config JSON,由预先工程化的 React 组件承载公式计算与渲染。路由是两段式:

1. `select_component` — LLM 只看**组件目录**(每组件一行),选出 componentId 与意图(create / adjust / off_catalog / chat);
2. `configure_component` — 按需注入选中组件的完整 schema 文档,LLM 产出完整 config(create)或**最小补丁**(adjust,只含变化字段),经 Zod 校验后渲染。

两条硬原则:

- **质量来自"组合被预先工程化"**。组件把物理/数学计算、光路/图形绘制、样式全部锁死,LLM 只可能配错参数,不可能画错图、写崩页面。
- **颗粒度 = 一个教学场景一个组件**。config 的每个字段必须是学生/老师会说出口的教学概念(焦距、浓度、频率),**绝不允许视觉概念字段**(位置、颜色、线段坐标)。出现视觉字段说明切太细;需要 `mode` 枚举覆盖多个场景说明切太粗,应拆成多个组件。

当前为 QA 实验阶段,代码在 `apps/web` 的 QA 目录下,不接触生产 agent/contracts。参考实现(样板)是 `physics.lens-imaging`,动工前先读这三个文件:

- `apps/web/src/lib/qa/components/lens-imaging.ts`
- `apps/web/src/app/qa/declarative-lens/widgets/lens-imaging.tsx`
- `apps/web/tests/declarative-lens-optics.spec.ts`

## 2. 一个组件的构成(五件套)

| # | 内容 | 位置 |
|---|---|---|
| 1 | 组件模块:config schema + patch schema + 纯计算函数 + `ImplementedComponent` 定义(含 schemaDoc/patchHints) | `apps/web/src/lib/qa/components/<短名>.ts` |
| 2 | 注册表登记:把组件定义加入 `COMPONENT_REGISTRY`(替换对应的 planned 占位条目,componentId 不变) | `apps/web/src/lib/qa/components/registry.ts` |
| 3 | React widget:config 驱动的渲染组件 | `apps/web/src/app/qa/declarative-lens/widgets/<短名>.tsx` |
| 4 | widget 登记:在 `WIDGETS` map 加一个条目(入口处 `ConfigSchema.parse(config)` 还原类型) | `apps/web/src/app/qa/declarative-lens/widgets/index.tsx` |
| 5 | 单测:覆盖规格中全部正确性判据 + 边界 | `apps/web/tests/declarative-<短名>.spec.ts` |

**只允许改动上述 5 处**。路由(`route.ts`)、页面外壳(`declarative-lens-client.tsx`)、类型定义(`types.ts`)对注册表是泛型的,新组件一律即插即用;如果你发现"不改核心文件做不到",停下来在交付说明里提出,不要自行修改。

## 3. config schema 规则

- 全部字段**必须有 `.default()`**(LLM 少给字段不能导致失败)、数值字段必须有 `.min()/.max()` 边界。
- patch schema 与 config schema 字段一致、全部 `.partial()`;每个字段必须**可独立修改**——不允许"改 A 必须同时改 B 才有效"的耦合字段。
- 字段名用教学语义的 camelCase(`focalLength`,不是 `f` 或 `x1`)。
- 枚举优先于布尔组合;禁止 `z.any()` / `z.unknown()` 字段。
- 字段数建议 3~7 个。超过 7 个先质疑颗粒度。

## 4. 计算层规则

- 教学计算(公式、曲线、步骤序列)写成**纯函数**放在组件模块里,禁止放进 React 渲染层。签名参考 `computeLensImage(config) → result`。
- 无随机性;若场景本质需要随机(如概率演示),必须接收显式 seed 并可复现。
- 处理数学奇点与边界(除零、定义域外、`u = f` 这类不成像点),返回显式的标记结果(如 `{ none: true }`),不允许 NaN/Infinity 泄漏到渲染层。

## 5. React widget 规则

- `"use client"`;props 固定为 `{ config: XConfig; onChange: (next: XConfig) => void }`,**唯一状态源是 config**。滑块、拖拽、切换等一切交互都通过 `onChange` 写回同一个 config——LLM 补丁与手动操作必须落在同一个对象上。播放/暂停这类纯瞬时 UI 状态可以用局部 state,但凡"学生调的参数"必须进 config。
- SVG 绘制:固定 `viewBox`,`width: 100%`,建立世界坐标 → 像素的映射函数(参考 lens 的 `X()/Y()`);禁止绝对像素布局假设。
- 颜色只从 `widgets/palette.ts` 的 `WIDGET_COLORS` 取,禁止新增 hex。
- 禁止:任何网络请求、DB 访问、外部 CDN、新 npm 依赖(需要第三方库时先在交付说明里提案,批准后才可用)、`dangerouslySetInnerHTML`。
- 基本 a11y:根 SVG 有 `role="img"` + `aria-label`,可交互控件可聚焦、有 label。
- 数值展示保留一位小数(参考 `fmt()`);读数用 chips 形式展示关键派生量(如像距、放大率)。
- 全参数域内(任意合法 config 组合)不允许版式爆炸或图形溢出 viewBox——极值要么裁剪 + 文字提示(参考 lens 的"像(很远)"),要么动态缩放。

## 6. schemaDoc 与 patchHints 规则

- `schemaDoc`:面向 LLM 的中文字段文档,逐字段列出含义、单位、范围、默认值,与 Zod 定义**逐项一致**(审核会对照)。
- `patchHints`:口语 → 字段变化的约定,覆盖该组件最常见的模糊说法(如"焦点以内"→ `objectDistance < focalLength`;"调大一点"→ 当前值 ±30%)。每个组件至少给 2 条。

## 7. 测试规则

- 新增 Vitest spec(`tests/*.spec.ts`,禁止自执行 `*.unit.ts`),必须覆盖:
  1. 本文第 9 节该组件的**全部正确性断言**(数值用 `toBeCloseTo`);
  2. 奇点/边界 case;
  3. schema:空对象出默认值、越界值被拒;
  4. patch schema:单字段补丁通过、越界被拒。
- `pnpm --filter @primoria/web typecheck`、`pnpm lint`、`pnpm --filter @primoria/web test` 三者全绿才算完成。

## 8. 交付物与流程

每个组件独立交付,包含:

1. 五件套代码;
2. 交付说明(md 或 PR 描述):字段设计的取舍、patchHints 覆盖的说法、已知局限(什么请求应降级)、若有依赖提案写明理由;
3. 测试输出(三个命令的结果);
4. QA 页实测记录:`PRIMORIA_ENABLE_QA_ROUTES=1` 起 dev server,在 `/qa/declarative-lens` 用真实 LLM 跑**至少 3 条 create + 3 条 adjust** prompt(含模糊口语说法),附输入与返回的 JSON。

审核(主导 Agent 执行)按第 10 节清单给出三态结论:入库 / 返修(附逐条问题)/ 拒绝(附理由)。

## 9. 待实现组件清单

### 第一批(componentId 已在注册表占位,不得改名)

#### 9.1 `chem.acid-base-titration` 酸碱滴定

- **范围**:v1 只做强酸强碱(HCl + NaOH)。弱酸/缓冲区/多元酸一律属于降级条件,写进交付说明。
- **config 草案**:`acidConcentration` mol/L [0.01, 0.5] 默认 0.1;`acidVolume` mL [10, 50] 默认 25;`baseConcentration` mol/L [0.01, 0.5] 默认 0.1;`addedBaseVolume` mL [0, 100] 默认 0;`indicator` enum `["phenolphthalein","methyl_orange","none"]` 默认 phenolphthalein。
- **交互**:滑块/按钮逐滴加碱(写回 `addedBaseVolume`),pH 曲线实时绘制,指示剂变色区间以色带标注,当前 pH 读数 chip。
- **正确性判据**(0.1M HCl 25mL,0.1M NaOH 滴定):加碱 0mL → pH=1.00;12.5mL → pH≈1.48;25mL(终点)→ pH=7.00;30mL → pH≈11.96。
- **注意**:pH 计算是纯函数 `computeTitrationPh(config)`;等当点附近曲线陡峭,采样要够密否则曲线失真。

#### 9.2 `physics.wave-superposition` 波的叠加

- **模型**:一维简谐波,y_i(x,t) = A_i·sin(2π·f_i·(t − x/v) + φ_i),波速 v 固定为 1(不进 config)。
- **config 草案**:`amplitude1`/`amplitude2` [0.2, 2] 默认 1;`frequency1`/`frequency2` Hz [0.5, 3] 默认 1;`phaseDiffDeg` 度 [0, 360] 默认 0;`showComponents` bool 默认 true(显示两列分波)。
- **交互**:滑块 + 播放/暂停(播放态是局部 UI state,不进 config),三条曲线(两分波 + 合成波)分色绘制。
- **正确性判据**(对纯函数在 t=0 断言):等幅等频、相差 180° → 合成波恒为 0;相差 0° → 合成幅值 2A;f1=2, f2=1 时合成波形周期为 1(取最小公倍周期)。
- **注意**:动画用 `requestAnimationFrame`,组件卸载时清理;曲线点数固定(如 200 点),不随参数变化。

#### 9.3 `cs.sorting-steps` 排序分步

- **config 草案**:`algorithm` enum `["bubble","selection","insertion"]` 默认 bubble;`values` `z.array(z.number().int().min(1).max(99)).min(4).max(10)` 默认 `[5,2,4,1,8,3]`。
- **交互**:上一步/下一步/自动播放(当前步序号与播放态为局部 UI state),当前比较对高亮、发生交换的元素动画标色,底部显示比较/交换计数。
- **正确性判据**:纯函数 `traceSort(algorithm, values)` 返回步骤序列(`{type:"compare"|"swap", i, j}`)。断言:bubble `[5,2,4,1]` → 比较 6 次、交换 5 次、结果 `[1,2,4,5]`;selection `[5,2,4,1]` → 交换 1 次、比较 6 次;任意输入的最终数组等于 `values` 排序结果。交付说明中写明算法变体定义(冒泡:每趟边界收缩、无提前退出;选择:仅 min≠i 时交换)。
- **注意**:`values` 是数组字段,补丁语义为整体替换;patchHints 要覆盖"换一组数据""再乱一点"这类说法。

#### 9.4 `math.function-explorer` 函数变换探索

- **模型**:y = a·f(b·(x − h)) + k。
- **config 草案**:`functionType` enum `["quadratic","sin","abs","sqrt"]` 默认 quadratic;`a` [-3, 3] 默认 1;`b` [0.25, 4] 默认 1;`h` [-5, 5] 默认 0;`k` [-5, 5] 默认 0;`showOriginal` bool 默认 true(灰线显示 f(x) 原型)。
- **交互**:四参数滑块;坐标系带网格与刻度;鼠标悬停显示 (x, y) 读数。
- **正确性判据**(纯函数 `evalTransformed(config, x)`):quadratic a=2,h=1,k=3 时 x=1 → y=3、x=2 → y=5;sin b=2 时周期为 π;abs a=-1 时图象翻转(x=2,h=0,k=0 → y=-2)。
- **注意**:sqrt 定义域 x ≥ h,域外不绘制、不产生 NaN;a=0 是合法值(水平线),不许崩。

## 10. 入库审核清单(审核者用)

**一票否决项**:

- 出现 `z.any()`/`z.unknown()` 字段,或 config 含视觉概念字段
- 未经批准引入 npm 依赖 / 修改第 2 节五处之外的文件
- 教学计算写在 React 渲染层内(不可单测)
- 网络请求 / DB 访问 / `dangerouslySetInnerHTML`
- 单测未覆盖规格里的正确性断言,或三个命令(typecheck/lint/test)不绿

**逐项检查**:

- G1 契约:字段全部教学概念、有界、有默认;patch 字段可独立修改;字段数合理;componentId 与占位条目一致
- G2 计算:纯函数、无随机(或 seeded)、奇点显式处理、断言数值与规格一致
- G3 渲染:全参数域无 NaN/溢出;交互全部写回 config;调色板合规;a11y 基线;动画正确清理
- G4 文档:schemaDoc 与 Zod 逐项一致;patchHints ≥ 2 条且覆盖常见口语;交付说明含已知局限
- G5 实测:QA 页 3 create + 3 adjust 真实 LLM 记录合理;含至少 1 条模糊说法(如"再快一点""换一组数")且补丁正确
