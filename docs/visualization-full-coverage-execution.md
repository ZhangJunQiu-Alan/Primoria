## 2. 依据、现状与覆盖边界

执行时以仓库当前代码、`AGENTS.md`、[文档优先级](README.md)、[交互组件规范](交互组件规范.md)和[集成回归规范](integration-regression-testing.md)为准。发生变化时更新当前态文档，不将本文当成已经实现的运行规范。

当前 Primoria 已有 19 个 Catalog 组件，以及专业渲染器、沙箱回退。课程 VisualBlock 尚需接入同一可信组件链路。参考站点的全量案例数尚未完成核实；已观察的物理引擎注册数、数学某学段列表数都不能作为全站总数。

- 通过内置浏览器检查 `/subjects` 的所有学段入口、学科、分页、分类和案例详情，包括不同入口下名称相似的案例。不要仅盘点物理和数学，也不要仅盘点默认展示页。

- 一个案例可能有多个页签、模型、阶段、预设或观察模式。全部教学能力进入该案例的验收子项，不能只实现默认画面。
- 案例名称别名、同一引擎重复注册、仅参数不同的预设不虚增组件数量；多案例共用一个组件时必须逐项证明教学能力等价。
- 本轮覆盖学科可视化内容。登录、支付、营销、账号系统等站点功能不属于复刻范围；若某入口本身提供学科可视化教学，则不能因名称不含“可视化”而遗漏。
- 对登录限制、失效链接或资源错误保留来源与阻塞证据。未验证项保持 `blocked` 或 `unverified`，不得从分母删除或标成已覆盖。
- 自行实现公式、绘制和教学交互；不把参照站点的专有脚本、素材、整段文案直接并入仓库。保存来源，区分实际观察与技术推断。

## 8. 场景实现与视觉标准

B 提供统一的场景绘制与控件基础，但只抽取已经出现的共性，不建无限通用的场景 DSL。

- 一个场景形成“要观察的问题 → 核心画面 → 可操作参数 → 实时读数/解释”的完整教学链。解释紧贴当前状态，不能只有静态装饰或模板化结论。
- 公式、轨迹、图表、数值读数来自同一个计算模型。处理零值、极值、奇点、单位、无解和越界，不用视觉近似掩盖错误计算。
- 颜色、线型、箭头、网格、标注、层次、留白和动效共同表达因果。减少无意义渐变和发光；色彩不能是唯一的信息通道。
- 优先 SVG/Canvas/已有可信依赖；确需 3D 再使用相应技术。技术选型以教学需要和可维护性为准，不因为参考画面有立体感就引入重型 3D。
- 支持视口调整、画布 DPR、触控和键盘控件、可见焦点、减少动态效果偏好。画面标签和读数不能在手机上溢出或重叠。
- 模拟时钟只应用一次速度系数；处理大帧间隔、暂停/重置、切换场景、卸载和重开。清理 RAF、Observer、监听器和图形资源，离屏/后台停止不必要动画。
- 按组件/学科懒加载，避免首页导入整库。动画热循环优先在绘制层运行，避免不必要的全树每帧 React 更新。
- 不在最终产品卡片显示内部 component ID、schema 名称、调试面板等实现信息。内部验收详情可展示这些证据。
- 图像、说明、坐标轴和动态数值必须可读；直接展示必要信息，不添加额外展开按钮。原有教学步骤、播放、重置、模式页签属于必要交互，可保留。

每个组件交付默认态、至少一个有教学意义的参数变化态，以及适用的边界/无解态。包含多个教学模式的案例必须逐模式验收。视觉验收比较信息表达和交互能力，不要求复制参考站点的品牌或像素。

## 9. 20 条随机真实 Prompt 的固定方案

A 在全站清单和组件库可用后生成 `apps/web/tests/fixtures/visualization-acceptance.prompts.v1.json`，使用记录在案的随机种子进行分层抽样，**先冻结输入及预期，再运行真实模型**。

固定分配：

| 维度 | 分配 |
| --- | --- |
| 入口 | 12 条普通对话新建 + 4 条基于其中已生成卡片的后续调整 + 4 条实际课程生成/VisualBlock，共 20 条用户 Prompt |
| 长度 | 短 6 条、中 8 条、长 6 条；在 fixture 中记录实际长度与分层规则 |
| 语言 | 中文 14 条、英文 4 条、中英混合 2 条 |
| 学科/学段 | 按实际快照分层，尽可能覆盖所有学科和各学段；学科数不超过 20 时不得漏掉整门学科，数量冲突在运行前通过分配算法解决 |
| 意图 | 覆盖解释、动态演示、对比、数值约束、生活化表达、自然语言省略，以及后续参数变化；不把所有输入写成标准模板名称 |

后续调整复用前面 12 条中的输出，不为准备上下文偷偷增加未记录 Prompt。课程 4 条必须走实际课程生成链路，不能只调用底层组件 API 假装建课成功。课程定位所需的确认可使用显式记录的测试资料/已有确认上下文，不向真实用户收集额外验收输入。

每个案例保存：

- `caseId`、随机种子、原始 Prompt、分层标签、父案例 ID、期望能力/可接受组件集合、参数约束、判定规则。
- 实际入口、provider/model、时间、run/request/tool IDs、原始选型结果、实际说明、组件 ID/版本、Web 验证后的 config 或 patch、最终状态。
- 延迟、实际 usage、检索/回退/错误信息、截图和必要交互断言。脱敏证据不包含 Cookie、Token、密钥、真实用户资料。
- 首次结果和全部后续尝试。失败案例不能删除或换成更容易的 Prompt；修复后重跑受影响项，保留修复前失败及原因。

20 条的实际运行使用现有模型配置，不顺手更换 provider、模型或温度策略。一个用户 Prompt 触发多次后端调用时，记录整条链的调用数和 usage，不能只统计最后一次。确定性/模拟模型回归单独标记，不计入 20 条真实模型实测。

库内明确请求若未产生正确可视化、调整覆盖无关参数、读数与配置矛盾、课程未生成对应块，均判失败。合理的交互控件变化可以在验收网页中操作，但不能再次请求模型生成输出。

## 10. 验收网页与证据包

页面包含：

回放必须复用生产 widget/计算实现及捕获 config；说明显示实际模型输出。无需生产 API、数据库、登录或模型密钥。加载页和操作已有控件不会调用生成接口。使用真实静态服务验证资源加载；若宣称支持 `file://`，必须实际验证，否则交付明确的本地服务启动命令和可点击地址。

验收页不放 Prompt 输入框、重新生成按钮或空白的“请先提问”入口。筛选库、切换案例、播放/暂停、改变本地教学参数属于允许的回放交互；提供重置到捕获结果的能力。

## 11. 测试和缺陷门槛

### 每批组件

- Schema、默认值、patch、非法字段/数值、边界和模式转换验证。
- 对关键公式/规律使用独立预期值或不变量，避免只测试“函数返回自己生成的数据”。
- Catalog ↔ registry ↔ widget map ↔ Agent 索引 ↔ Schema/版本同步检查。
- SSR/客户端加载、无障碍控件、重置、暂停、销毁、实例隔离、语言和响应式布局检查。
- 对新类别、易混淆概念和每个场景家族补路由正反例；保留所有原有路由政策。

### 生产链路

- 普通对话真实工具选择 → Web 配置 → 直接渲染；同一卡片连续调整，取消、超时、重试和乱序响应。
- 刷新/重开不重复生成；账号切换不泄漏；未知组件/版本安全失败。
- 真实课程生成 → VisualBlock → 保存/重新打开 → 不可变分享快照 → 导入后显示。旧课程和旧快照保持可读。
- Web 认证/owner 隔离、参数校验、请求预算及服务端错误脱敏保持有效。
- 20 条真实模型输入有对应浏览器展示和证据，不仅有 API 状态码。

### 全库视觉与性能

B 逐案例/模式核对教学能力，批量截图结合实际交互检查；A 验证生产入口与回放入口。至少检查手机 390px、平板 768px、桌面 1440px，记录浏览器和 DPR。

使用固定设备/浏览器记录首帧、资源体积、主要动画帧耗时、重复打开/关闭后资源释放；和改动前同条件基线比较。遵守既有 bundle gate，不能一次加载全库。性能未达标时调整实现并重新验证；不得凭主观“流畅”声称通过，也不得把 20 个样本的统计推成全用户 SLA。

完整工程收口执行：

```bash
pnpm catalog:validate
pnpm --filter @primoria/web test:interactive-routing
pnpm test:learning-goal-routing
node --check apps/agent/src/graph.mjs
pnpm test:regression
```

前四项可用于批次反馈；最终完整回归包含 fast/build/db/browser，已通过的同一代码基线无需无理由重复整套。新增可视化覆盖/回放检查必须加入可重复执行脚本及适当 CI 层；新脚本由 A 在实现后补充准确命令，不在报告中将尚不存在的命令写成已运行。

Web 新测试写原生 `tests/*.spec.ts`；Agent 测试保持 plain ESM。禁止删测试、降低阈值、跳过失败断言来“通过”。永久学习目标语料保持至少 1,718 个案例，现有 gold policies、31 个运行图及既有回归不得削减。
