# 科目文件夹：按讲累积的私有 KG 与自适应选择题测验

Status: approved design; all four phases implemented (2026-10-24).
Extends [`learning-materials.md`](learning-materials.md); runtime code, schemas,
and tests remain the source of truth once implemented.

## 1. 目标

参考 NotebookLM，用**文件夹**管理一个科目（如"H5+CSS3"、"Information Security"）。
学习者把一讲讲的资料（PDF）陆续放进文件夹：

```text
文件夹（科目） ── 大 KG（id 永久固定，掌握度一直累积）
  ├─ 第 1 讲.pdf ── 小 KG
  ├─ 第 2 讲.pdf ── 小 KG   ← 按文件名 / AI 判断排在第 1 讲之后
  └─ 大纲.pdf    ── 参考资料（不进 KG 顺序链，只作出处）
```

系统按讲生成小 KG，并把它们按顺序拼成整个科目的大 KG。学习者可以随时对整个大 KG 做
选择题测验：越薄弱的概念出题越多，答题结果按规则写入掌握度。

## 3. 模型

- **文件夹**（`material_folders`）：owner 私有，有名称；每人另有一个系统"未分类"文件夹。
- **文件**：现有 `learning_materials` 增加 `folder_id`、`role`（`lecture` | `reference`）、
  `position`（文件夹内排序键）、`order_source`（`filename` | `ai` | `manual`）、
  `kg_status`（`pending` | `processing` | `ready` | `failed` | `skipped`）。
- **小 KG**（`material_subgraphs`，每个讲义文件一行）：该讲的 topics/concepts、讲内先修边、
  每个概念引用的片段，以及 AI 给出的 `sameAs`（与已有概念相同）和 `requires`（依赖已有概念）。
- **概念身份**：没有单独的概念表。小 KG 里的每个概念直接带文件夹级 id：新概念生成新 id
  （`fc_<随机>_<slug>`），`sameAs` 命中的概念沿用已有 id，出处在拼装时汇总（每概念最多 12 段）。
  **掌握度键是 (owner, 文件夹图 id, 概念 id)**，所以拼装、重排、插入或删除讲都不改变已有概念 id。
- **掌握度表**：`user_concept_mastery` 有一条指向题库 KG 概念表（`knowledge_graph_concepts`）的外键，
  `mat_*` 概念不在那张表里，所以 `mat_*` 图（文件夹图与第一阶段的资料组合图）的掌握度写入同列同规则的
  `material_concept_mastery`；`apps/web/src/lib/mastery/owner-store.ts` 按 graph id 路由。与第一阶段一致，
  图谱或文件夹删除后掌握度行保留（owner 私有，随账号删除）。
- **大 KG**：确定性拼装产物，写入现有 `material_topic_graphs`，graph id 为
  `mat_<hash(folderId)>`。沿用 `mat_` 前缀意味着现有的私有化规则全部自动适用：owner 才能解析、
  课时图片私有、课程不能分享、侧栏 Tutor 资料问答、学习进度/Extractor 解析。

## 4. 流程

### 4.1 上传到文件夹

```text
POST /api/materials (folderId, role) → 抽取 + 分块（不变）→ kg_status = pending
  → 入队 material_kg_jobs（Postgres lease/fencing，同一文件夹串行）
worker:
  1. 小 KG：一次模型调用，输入本讲资料目录 + 文件夹已有概念清单
     → 本讲概念（引用片段）+ sameAs + requires
  2. 排序：文件名序号可解析则按序号；否则一次轻量模型调用决定插入位置
  3. 拼装大 KG（纯函数，无模型调用）→ upsert material_topic_graphs
  4. after()：片段 embedding 索引（已有）
```

- 队列放在**现有 Extractor worker 进程**里处理（它已经同时消费两个队列），不新增部署容器。
- **同一文件夹串行**：保证 `sameAs` 总是对照最新的概念清单，避免并发产生重复概念。
- 参考资料文件跳过第 1–3 步（`kg_status = skipped`），只做索引。

### 4.2 拼装算法（确定性）

1. 讲义按 `position` 排序。
2. 概念归并：分析一讲时 `sameAs` 直接沿用已有概念的 id，所以同一概念的 id 由最早**分析**
   的那一讲决定（与排序无关，保证 id 稳定）；概念放在含有它的讲中**排序最靠前**那一讲的位置，
   其余讲只并入出处。
3. Topics 按讲顺序拼接（topic id 带文件前缀），被合并走概念而变空的 topic 丢弃。
4. 边：讲内链 + 相邻讲首尾边 + AI `requires` 边（只保留指向更早位置的边，结果必为 DAG）。
5. 拼装在上传完成、拖动排序、改角色、删除文件时重跑；不调用模型，毫秒级。

### 4.3 删除文件

- 允许删除；重新拼装后该讲独有的概念离开大 KG，掌握度行保留（owner 私有）。
- 已生成的课时内容保留，来源标注随之消失；只覆盖被删概念的**未生成**课时从大纲移除。
- 这替代了第一阶段"有课程在用就禁止删除"的规则（该规则继续适用于旧的资料组合课程）。
- 实现：每次 `rebuildFolderGraph` 后由 `reconcileFolderCourses`（`folder-course-reconcile.ts`）处理建在
  该文件夹图上的课程——课时的 topic 锚点跟随它的第一个仍在图中的概念（文件夹图的 topic id 按讲生成，
  排序、删除、改角色都会让概念换到别的 topic），所有概念都已离开大 KG 的 `planned`、未生成课时被删除；
  已生成的课时保留（其概念若全部离开，课时内容仍可读，但学习进度无法再归到这些概念上）。

### 4.4 按 KG 生成课程

- 与现有建课完全同一思路：复用 `initializeCourseOutline` 的 concept-frontier 大纲，按大 KG 的
  顺序把未掌握的概念每 2–3 个一组做成一节计划课时，scope key 为 `graph:<mat 文件夹图>:full`。
- 课程大纲是创建时的快照；之后新增的讲，通过"同步新内容"把新概念按 KG 顺序插入为计划课时。
- 实现（`apps/web/src/lib/materials/folder-course.ts`）：`POST /api/folders/[id]/course` 建课或返回已有课程
  （每个文件夹一门，首节课进入生成队列）；`GET` 返回课程与可同步的新知识点数；
  `POST /api/folders/[id]/course/sync` 插入计划课时。新概念 = 大 KG 中没有任何课时覆盖、也未掌握的概念；
  先按"排在第一个讲授更靠后概念的已有课时之前"划分到各个空档，再在每个空档内用同一个 concept-frontier
  每 2–3 个一组（新课时不会混合两个空档的概念），排序键取空档两端之间的分数。课时 id 由课程与概念集合
  决定，重复同步不会重复插入。文件夹详情页的"课程"卡片：建课、继续学习、同步新内容。
- "勾选资料建课"仍然保留，用于针对少数文件单独建课（第一阶段的资料组合课程）。

### 4.5 自适应选择题测验

```text
POST /api/folders/:id/quizzes { size: 10 | 20 }
  1. 读大 KG 概念 + 该图的掌握度
  2. 分配：权重 薄弱 4 / 未测 3 / 学习中 2 / 已掌握 0.5；每概念每次最多 2 题；
     已掌握的复习题每次最多 1 道（种子随机，便于测试）
  3. 选题：优先该概念中学习者从未作答过的题；不够则一次模型调用批量生成
     （输入每个概念的引用片段，题目必须能在资料中找到答案；系统指定 conceptId）
  4. 返回题目（不含答案）
POST /api/folders/:id/quizzes/:sessionId/submit { submissionId, answers }
  → 判分 + 解析 + 出处；幂等（submissionId + 唯一约束，同课程测验）
  → 写 quiz 证据事件（只计每道题的第一次作答）→ 掌握度更新（见 §5）
```

新增表（迁移 0061）：`folder_quiz_questions`（题库：概念、语言、题干、已打乱的 4 选项、正确项、解析、
出处片段、生成版本）、`folder_quiz_sessions`（一次测验的题目列表、状态、submissionId、判分结果）、
`folder_quiz_answers`（每道题的作答；`(owner, question)` 上只允许一条首次作答，滚动窗口读这张表）。

实现细节（`apps/web/src/lib/materials/folder-quiz.ts` 纯函数、`folder-quiz-store.ts` 读写）：

- 分配时已掌握概念的复习题上限只在较弱概念还能填满测验时生效；全部掌握（或较弱概念不够）时，
  已掌握概念补足剩余题量（仍每概念最多 2 题）。概念太少时测验会短于 10/20 题，页面会说明。
- 题库按语言区分：出题语言取设置里的内容语言，没有设置时取文件夹资料的多数语言。
- 生成只针对"未答过的题不够"的概念，一次调用，90 秒超时；每个概念最多 3 段、共 24k 字符的引用片段，
  没有片段的概念不出题；题目引用的片段必须属于该概念，否则回退到该概念的全部片段。选项在入库时打乱。
  生成失败时用题库已有题目继续；一题都没有才返回 503 `quiz_generation_failed`。
- 题目按大 KG 顺序（一讲一讲）排列，每题标注所属讲和概念；答案只在提交后返回。
- 提交在同一事务里判分、写作答、更新掌握度并调用 `applyMasteryProgression`（已掌握成就/每日任务），
  事务先锁文件夹行，保证同一文件夹的提交串行、首次作答判定准确。未作答的题算错但不计证据。
  测验本身不发 XP。中途刷新页面会放弃未提交的测验（题目留在题库里，下次优先使用）。
- 文件夹详情页的"测验"面板：开始 10 题 / 20 题、作答、提交（失败重试复用同一 submissionId）、
  逐题对错与解析和出处、掌握度变化，提交后刷新 KG 概览。

## 5. 测验如何累积掌握度（已决定：方案 A）

现有规则按**单节课**的答题计算：一个概念要在同一节课的测验里答满 3 题且正确率 ≥ 80% 才算掌握，
每次重新计算、不跨课累积。整个 KG 出 10 题、每概念每次最多 2 题时，单次测验永远凑不满 3 题，
概念会一直停在"学习中"。两个选项：

- **A（推荐，已实现：`computeRollingMasteryUpdates`）滚动窗口**：测验路径按该概念**最近 5 次首次作答**
  计算（仍要求 ≥ 3 题且 ≥ 80%；已掌握后答错降为学习中，与现规则一致）。覆盖面广，掌握度在多次测验中
  逐步收敛。课时测验路径保持现有的按课计算不变，两条路径写同一掌握度行，以最近一次为准。
  已掌握的概念（无论来自哪条路径）只会因为本次答错而降级，窗口里题数不足 3 时答对不会让它掉级。
- **B 集中练**：每次测验只挑 3 个最薄弱的概念、每个出 3 题（10 题 = 3×3 + 1 道复习）。
  沿用现规则不改，但单次测验覆盖面窄。

## 7. 风险与限制

- 概念合并依赖模型判断：误合并会把两个概念的掌握度混在一起，漏合并会出现重复概念。
  第一版不提供手动合并/拆分（以后再加）。
- 跨讲依赖只允许指向更早的讲；如果真实课程中后面的讲是前面的先修，需要学习者手动调整顺序。
- 测验题只做单选，不能考察推导和开放性理解；简答/判分留到以后。
- 单个 PDF 若是整门课（几百页），小 KG 仍沿用资料图谱的上限（≤ 12 个 topic、每个 ≤ 3 个概念），
  内容多的整本教材会被压缩；以后再按资料规模放宽。
- 只有分析失败的讲义可以重试；已完成的讲义不会重新分析（重新分析会换掉它独有概念的 id）。
- 发给模型的已有概念清单最多 300 个，超出部分无法被 `sameAs` 命中。
- 同步只会新增课时，不会重写已有课时的标题或概念分组；新课时使用概念名模板标题（不做大纲润色调用）。

## 8. 分阶段交付

1. **文件夹基础**（已实现）：`material_folders` 与迁移 0058（为已有资料建每人的"未分类"文件夹并按
   上传时间回填）、文件角色、文件名序号解析与插入（`apps/web/src/lib/materials/ordering.ts`）、
   手动排序与跨文件夹移动（`folders.ts`，`/api/folders/**`、`PATCH /api/materials/[id]`）、
   `/materials` 文件夹列表与 `/materials/[folderId]` 文件夹详情。此阶段建课仍沿用"勾选资料建课"。
2. **按讲 KG**（已实现）：迁移 0059（`material_kg_jobs`、`material_subgraphs`、
   `learning_materials.kg_status`、`material_topic_graphs.folder_id`；已在科目文件夹里的讲义会被回填入队）
   与 0060（`material_concept_mastery`）。队列在 Extractor worker 内处理，优先级为资料事实 → 讲义 KG →
   Extractor，同一文件夹串行，最多 2 次尝试，`/api/health` 报告 `lectureKg` 队列与心跳
   （`lecture-kg-jobs.ts`、`lecture-kg-processor.ts`）。小 KG 复用资料图谱提示词并附上文件夹已有概念
   （K1…，最多 300 个）；文件名没有序号、学习者也没手动排过序时，一次轻量调用决定插入位置
   （`lecture-order.ts`，位置来源记为 `ai`）。拼装是纯函数（`folder-graph.ts`），由
   `rebuildFolderGraph`（`folder-graph-store.ts`）在分析完成、排序、改角色、移动、删除、重命名时重跑。
   讲义改为参考资料再改回时复用已有小 KG；移到别的科目会删除小 KG 并按新文件夹重新分析。
   文件夹详情页显示每讲的分析状态（失败可 `POST /api/materials/[id]/kg` 重试）、分析中每 5 秒刷新，
   以及按讲列出概念与掌握度的 KG 概览（`GET /api/folders/[id]/graph`）。
3. **自适应选择题测验**（已实现）：见 §4.5 实现细节与 §5；路由 `POST /api/folders/[id]/quizzes`、
   `POST /api/folders/[id]/quizzes/[sessionId]/submit`。
4. **从文件夹建课**与"同步新内容"（已实现）：见 §4.3、§4.4 的实现说明。
