# 科目文件夹：按讲累积的私有 KG 与自适应选择题测验

Status: approved direction, design for review, not yet implemented (2026-10-24).
Extends [`learning-materials.md`](learning-materials.md); runtime code, schemas,
and tests remain the source of truth once implemented.

## 1. 目标

参考 NotebookLM，用**文件夹**管理一个科目（如"H5+CSS3"、"Information Security"）。
学习者把一讲讲的资料（PDF）陆续放进文件夹：

```text
文件夹（科目） ── 大 KG（id 永久固定，掌握度一直累积）
  ├─ 第 1 讲.pdf ── 小 KG
  ├─ 第 2 讲.pdf ── 小 KG   ← 按文件名 / AI 判断排在第 1 讲之后
  └─ 大纲.pdf    ── 参考资料（不进 KG 顺序链，只作出处）
```

系统按讲生成小 KG，并把它们按顺序拼成整个科目的大 KG。学习者可以随时对整个大 KG 做
选择题测验：越薄弱的概念出题越多，答题结果按规则写入掌握度。

## 3. 模型

- **文件夹**（`material_folders`）：owner 私有，有名称；每人另有一个系统"未分类"文件夹。
- **文件**：现有 `learning_materials` 增加 `folder_id`、`role`（`lecture` | `reference`）、
  `position`（文件夹内排序键）、`order_source`（`filename` | `ai` | `manual`）、
  `kg_status`（`pending` | `processing` | `ready` | `failed` | `skipped`）。
- **小 KG**（`material_subgraphs`，每个讲义文件一行）：该讲的 topics/concepts、讲内先修边、
  每个概念引用的片段，以及 AI 给出的 `sameAs`（与已有概念相同）和 `requires`（依赖已有概念）。
- **概念身份**（`folder_concepts`）：文件夹内每个概念一个稳定 id，记录它最早创建于哪个文件、
  合并进来的同义概念、汇总的出处。**掌握度键是 (owner, 文件夹图 id, 概念 id)**，所以拼装、
  重排、插入新讲都不改变已有概念 id。
- **大 KG**：确定性拼装产物，写入现有 `material_topic_graphs`，graph id 为
  `mat_<hash(folderId)>`。沿用 `mat_` 前缀意味着现有的私有化规则全部自动适用：owner 才能解析、
  课时图片私有、课程不能分享、侧栏 Tutor 资料问答、学习进度/Extractor 解析。

## 4. 流程

### 4.1 上传到文件夹

```text
POST /api/materials (folderId, role) → 抽取 + 分块（不变）→ kg_status = pending
  → 入队 material_kg_jobs（Postgres lease/fencing，同一文件夹串行）
worker:
  1. 小 KG：一次模型调用，输入本讲资料目录 + 文件夹已有概念清单
     → 本讲概念（引用片段）+ sameAs + requires
  2. 排序：文件名序号可解析则按序号；否则一次轻量模型调用决定插入位置
  3. 拼装大 KG（纯函数，无模型调用）→ upsert material_topic_graphs
  4. after()：片段 embedding 索引（已有）
```

- 队列放在**现有 Extractor worker 进程**里处理（它已经同时消费两个队列），不新增部署容器。
- **同一文件夹串行**：保证 `sameAs` 总是对照最新的概念清单，避免并发产生重复概念。
- 参考资料文件跳过第 1–3 步（`kg_status = skipped`），只做索引。

### 4.2 拼装算法（确定性）

1. 讲义按 `position` 排序。
2. 概念归并：`sameAs` 形成等价类，类的 id = 最早**创建**的成员（与顺序无关，保证 id 稳定）；
   概念出现在类中**排序最靠前**那一讲的位置，后续讲的同义概念只并入出处。
3. Topics 按讲顺序拼接（topic id 带文件前缀），被合并走概念而变空的 topic 丢弃。
4. 边：讲内链 + 相邻讲首尾边 + AI `requires` 边（只保留指向更早位置的边，结果必为 DAG）。
5. 拼装在上传完成、拖动排序、改角色、删除文件时重跑；不调用模型，毫秒级。

### 4.3 删除文件

- 允许删除；重新拼装后该讲独有的概念离开大 KG，掌握度行保留（owner 私有）。
- 已生成的课时内容保留，来源标注随之消失；只覆盖被删概念的**未生成**课时从大纲移除。
- 这替代了第一阶段"有课程在用就禁止删除"的规则（该规则继续适用于旧的资料组合课程）。

### 4.4 按 KG 生成课程

- 复用 `initializeCourseOutline`，scope key 为 `graph:<mat 文件夹图>:full`。
- 课程大纲是创建时的快照；之后新增的讲，通过"同步新内容"把新概念按 KG 顺序插入为计划课时
  （放在第 4 阶段）。

### 4.5 自适应选择题测验

```text
POST /api/folders/:id/quizzes { size: 10 | 20 }
  1. 读大 KG 概念 + 该图的掌握度
  2. 分配：权重 薄弱 4 / 未测 3 / 学习中 2 / 已掌握 0.5；每概念每次最多 2 题；
     已掌握的复习题每次最多 1 道（种子随机，便于测试）
  3. 选题：优先该概念中学习者从未作答过的题；不够则一次模型调用批量生成
     （输入每个概念的引用片段，题目必须能在资料中找到答案；系统指定 conceptId）
  4. 返回题目（不含答案）
POST /api/folders/:id/quizzes/:sessionId/submit { submissionId, answers }
  → 判分 + 解析 + 出处；幂等（submissionId + 唯一约束，同课程测验）
  → 写 quiz 证据事件（只计每道题的第一次作答）→ 掌握度更新（见 §5）
```

新增表：`folder_quiz_questions`（题库：概念、题干、4 选项、正确项、解析、出处片段、生成版本）、
`folder_quiz_sessions`（一次测验的题目列表、状态、提交时间、submissionId）。

## 5. 需要你决定：测验如何累积掌握度

现有规则按**单节课**的答题计算：一个概念要在同一节课的测验里答满 3 题且正确率 ≥ 80% 才算掌握，
每次重新计算、不跨课累积。整个 KG 出 10 题、每概念每次最多 2 题时，单次测验永远凑不满 3 题，
概念会一直停在"学习中"。两个选项：

- **A（推荐）滚动窗口**：测验路径按该概念**最近 5 次首次作答**计算（仍要求 ≥ 3 题且 ≥ 80%；
  已掌握后答错降为学习中，与现规则一致）。覆盖面广，掌握度在多次测验中逐步收敛。
  课时测验路径保持现有的按课计算不变，两条路径写同一掌握度行，以最近一次为准。
- **B 集中练**：每次测验只挑 3 个最薄弱的概念、每个出 3 题（10 题 = 3×3 + 1 道复习）。
  沿用现规则不改，但单次测验覆盖面窄。

## 6. 迁移与兼容

- Drizzle 迁移新增文件夹表；为每个已有资料的学习者建"未分类"文件夹并回填 `folder_id`。
- 第一阶段"选 1–5 份资料建课"生成的 `mat_*` 课程与图谱保持原样可用；新建课入口改为从文件夹进入。
- `/materials` 页面改为"文件夹列表 → 文件夹详情（按讲排序的文件、拖动排序、KG 概览、测验、建课）"。

## 7. 风险与限制

- 概念合并依赖模型判断：误合并会把两个概念的掌握度混在一起，漏合并会出现重复概念。
  第一版不提供手动合并/拆分（以后再加）。
- 跨讲依赖只允许指向更早的讲；如果真实课程中后面的讲是前面的先修，需要学习者手动调整顺序。
- 测验题只做单选，不能考察推导和开放性理解；简答/判分留到以后。
- 单个 PDF 若是整门课（几百页），小 KG 的 topic 上限需要放宽到与资料规模匹配（实现时定）。

## 8. 分阶段交付

1. **文件夹基础**：文件夹表与迁移、文件角色与排序（文件名解析 + 手动拖动）、`/materials` 改版。
2. **按讲 KG**：`material_kg_jobs` 队列、小 KG（sameAs/requires）、AI 排序兜底、确定性拼装、
   文件夹 KG 概览（按讲列概念与掌握度）、删除后重拼。
3. **自适应选择题测验**：题库、分配、生成、提交、掌握度累积（§5 的决定）。
4. **从文件夹建课**与"同步新内容"。
