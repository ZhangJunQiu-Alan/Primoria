# 6. Version Control Practice

Last updated: 2026-04-05

## Objective

Document how Git/GitHub is used to support traceable, iteration-based delivery.

## Repository and Branching

- Primary repository: `Primoria` on GitHub.
- Main integration branch: `main`.
- Work item branches (recommended): `feature/*`, `fix/*`, `docs/*`, `chore/*`.

## Commit Practice

- Use atomic commits with clear scope:
  - `feat: ...`
  - `fix: ...`
  - `docs: ...`
  - `chore: ...`
- Keep commit messages focused on behavior change and evidence.

## Pull Request Practice (Recommended Standard)

1. Create branch from `main`.
2. Link PR to issue/user-story ID.
3. Include test evidence in PR description.
4. Pass CI checks before merge.
5. Merge and update changelog/docs.

## Traceability Pattern

Requirement -> Issue -> Branch -> PR -> Merge commit -> Release note

Use this linkage to justify rubric criteria for version control and agile delivery.

## Improvements for Higher Rubric Band

1. Enforce branch protection on `main` (PR required, checks required).
2. Require issue links in PR template.
3. Require at least one reviewer for non-trivial changes.
4. Tag iteration releases (for example `iter1`, `iter2`, `iter3`).
